# Noema 产品章程

本文维护长期产品边界；运行事实由代码、验证结果与标注清楚的逻辑流程说明。阶段进展见 ROADMAP，具体工作见 OpenSpec change。

## 产品方向

Noema 是用户拥有的个人 agent 应用，身份、连续性与长期状态独立于模型和外部 harness。持续交流本身有价值，分享、倾诉、探索不必被解析成任务。产品既需要可靠办事，也希望支持长期相处与个体发展；这些目标不等于意识或主观体验已经成立。

Noema 是主要交谈对象。需要行动时可借助持久的专业成员，分离高层交流判断与细碎执行；群聊、委派和计划服务于这种关系，不代表整个产品定位。编程是一种使用场景。

## 已采用的设计边界

- 用户保有目标、重要价值取舍与最终验收；工程实现和普通可逆决定由 agent 承担。
- 真实委托先弄清必要目标与约束，证据可能改变判断时安排有边界的研究，再决定个人执行或团队协作；普通交流不强制进入该流程。
- 群聊消息公开可见，显式 @ 控制定向唤起；@所有人与持续共同讨论不同。计划服务团队，用户界面应帮助快速理解状态，而非暴露全部内部工作表。
- Noema 保持连续主会话，专业成员具有自身资产与项目上下文。成长由成员基于经历审视并修改自身，Noema 负责协调；成长质量需要后续实践检验。
- 自主行动与探索在用户知情授权的范围和预算内发生；停止、失败、重启和恢复不能制造已完成假象。

## 留给实际使用的判断

商业画像、最终品牌、关系体验与成长价值仍需真实使用校准。基础能力参考成熟实现的完整契约；差异可以来自更好的执行与组合，不要求凭空创造功能。
