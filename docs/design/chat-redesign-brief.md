# Noema 聊天与行动基线

当前决策与推进状态见 [ADR 0026](../decisions/0026-noema-first-chat-and-visible-actions.md) 与 [Issue #104](https://github.com/c3115644151/noema-agent/issues/104)。本 brief 只保存界面和产品实现共同遵循的验收边界。

## 交互模型

- Noema 私聊是默认入口。日常交流、探索、写作和一般计划留在连续对话中；用户不应每轮选择回应者或先切换“聊天/执行”模式。
- Noema 依据实际可用能力组织协作。当前文件工作使用应用自有的有界工具循环；知识委派仍是一次性调用，不能将它描述成已完成的多成员项目调度或自动跟进能力。
- 真正开始文件执行时，用户要先选择工作区并看到数据流、Windows 执行限制和停止不回滚说明。执行状态靠近来源请求显示真实执行者、范围、状态、结果与独立核验。
- 专业 agent 私聊和群聊作为可主动进入的交流方式保留；不要把一次内部路由伪装成联系人、群聊或合成消息。
- 有文件能力的专业成员也通过普通消息使用工具。工具选择、上下文组装和历史案例处理属于运行机制，不在输入框前设置“聊天/项目工作”切换或经验复用勾选项。用户保留工作目录、执行状态和停止操作等有实际后果的控制。
- 短期追问留在原聊天。跨日主题线程遵循 ADR 0025；它保存对话，不代表定时运行或自动监控。

## 导航与信息层级

- Noema 私聊固定为唯一主聊入口；专业联系人、群聊和主题线程作为其他聊天保留。主聊优先级不依赖最近活跃时间，也不把内部执行者提升成新对话。
- 模型属于运行设置，不占据主聊天顶部的常驻空间；连接问题在需要用户处理的输入区域呈现。
- 聊天区域按通信应用连续铺开，不用嵌套面板模拟产品价值。执行卡片因拥有独立的真实状态而保留，但必须贴近其来源消息。

## 不变量与可调整项

消息来源、房间隔离、能力校验、明确工作区授权、停止/失败状态、结果核验和可追溯性是质量底线。视觉语言、侧栏组织、联系人的显著程度、群聊回应机制及任务卡的呈现可以基于真实使用调整。

讨论或模型推测不等于行动。没有用户授权和实际实现能力，就不创建执行状态。普通对话不自动生成经历总结、永久记忆或新 agent。任何持续状态都要有清楚的 owner、生命周期、成本和撤回路径。

## 界面验收

界面应服务连续交流和可理解的行动结果，呈现有辨识度的 Noema 品牌与足够的信息密度；不能依赖通用 AI 聊天模板、工程控制台或装饰性面板来表达产品价值。设计前写清用户情境、信息优先级、关键状态和主要取舍；实现后在运行应用中检查正常、空、加载、失败、停止/恢复和窄窗状态。只有实际检查过的状态才报告完成。

逐阶段替换旧 root 和逐轮选择执行者的实现前，先核查迁移涉及的 captures、导入内容、旧互动约定数据与未完成任务，保证用户状态可访问且迁移可追溯。互动约定不再作为当前聊天中的独立管理/注入功能；历史数据暂留在本机，不进入新请求。
