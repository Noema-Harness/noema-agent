# Noema 产品探索与完整界面重设计

当前工作与续接点见 [Issue #104](https://github.com/c3115644151/noema-agent/issues/104)。Noema 当前是基础 demo；产品的具体用途、选择理由与品牌仍需设计，不能从现有功能中倒推出答案。

## 已确认的范围

Noema 是独立的个人 agent 应用，追求与用户持续交流和个体化；外部 agent 协作是可选能力。交互倾向微信、Telegram 类通信习惯，不做 AI 酒馆或工程编排工作台。整个界面都在重设计范围内：信息结构、操作过程、排版、色彩、图形、文案、动效与主要状态。旧界面和现有架构是可修订的原型材料。

## 分别判断、共同设计

**产品探索：**在什么具体日常情境下，用户为什么会需要 Noema？现在怎样解决，现有选择的缺口是什么，拟议体验如何改善结果或降低代价？现有代码用于判断可行性、缺口和复用/删除成本，不是定位依据。记忆、提示词策略、多 agent 和房间只是能力或实现选项；不能通过重新命名使其成为独特价值。方案可以采用成熟方法，不为追求新奇堆功能；没有成立的产品主张时，如实保留未定结论。

**界面与品牌：**在期望使用过程中，如何形成清楚、一致、有辨识度的表达？成熟通信交互可以保留惯例，视觉语言可通过构图、排版、密度、图形、材质、色彩、文案与动效的明确取舍建立。不能要求先找到独特技术机制才做设计，也不能用视觉完成度证明产品价值。需要具体设计参考和有理由的审美判断，不把助手默认模板当作方案。

两类工作需要不同证据，但属于同一个产品设计过程。产品未定时，助手应主动探索用途、缺失能力与期望体验，让这些判断约束布局、信息密度和表达；界面推演暴露出的产品缺口也应反过来修订产品方案。不能把“视觉不必等待独特功能”解释为仅做前端，也不能把“不得从 demo 倒推需求”解释为回避核心产品设计。前端同质化不自动意味着应把某项现有功能升格为核心定位。

## 当前设计任务：功能价值与个人伙伴体验

用户已肯定折面样稿的设计质量，同时判断它不适合 Noema 当前预期：复古潮流气质、大面积身份展示和偏低的信息密度，更像娱乐/情感角色展示，未支撑功能服务型个人 agent 的使用价值。该稿保留为方法实验，不再作为待认可的 Noema 界面候选。

用户明确的产品取向是功能服务与个人专属伙伴可以同时成立；命名的文艺、哲学意味是品牌线索。以下为助手判断：名字不能直接推出字体/配色，高信息密度也不能直接推出更多面板。应先判断用户需要同时掌握哪些内容、进展、成果与可介入动作；温度可以体现在理解、表达、协作节奏和长期相处中，无需由大头像或角色展示区承担。

当前检查的代码仅提供实现证据：普通聊天按房间组织模型回复，`social-chat-store.mjs` 的 `getContext` 提供近期消息与项目任务；`social-work-service.mjs` 的 `startTask` 通过选择目录启动项目文件工作。互动约定、群聊与任务结果已是可用原型材料，但这些主路径尚不能证明日常功能服务、跨日承接或个人伙伴价值已经成立。后续允许增加、删去或重组行为，不以既有房间和项目工作为产品答案。

已核实的外部反例：[Claude Cowork 官方产品说明](https://claude.com/resources/guides/claude-cowork-product-guide/product-overview)已覆盖文件/应用工作、可交付文档、长任务、计划任务和持久项目；[当前帮助说明](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork)还描述聊天与工作共享入口、部分账户逐步合并为统一体验。它说明“聊天加执行”“持久项目”本身不足以成为 Noema 的区别，不证明它已满足所有个人用途。这是官方能力说明核查，未完成该产品的实机体验或长期效果测量。

## 助手推荐的产品假设：共同想清楚，持续做下去

状态：供产品方向评审的建议，尚未获用户选择、未实现，也没有证明优于成熟替代。推荐的是一项有明确取舍的使用主张，不是宣称发现了全球独占功能。

**Noema 帮用户把尚未想清楚的事逐渐做成：参与形成判断，承担可以委托的推进，并在方向改变后让相关工作保持一致。** 持续对话是入口；用户正在做的事及可继续使用的成果，是回来的理由。专属伙伴的熟悉感来自共同经历中的具体理解和合适的主动性，不依靠人格展示区或亲密话术。

首轮验证对象暂定为已常用 AI 的个人研究者、独立创作者和自主学习者：他们有跨多次对话的事情，目的会变化，愿意参与重要判断，也希望把搜集、整理、试做等工作交出去。这是助手选择的用户假设，不是用户画像研究结论；写作场景只是首个压力情境，不将 Noema 永久缩成写作工具或把所有聊天变成项目。

同一个 Noema 仍是持续交流的伙伴。“一件事”组织的是当前相关的资料、判断与成果，不是新建一个人格，也不要求用户每次先选项目。普通聊天可以有自己的价值，只有确实要持续推进时才建立相应状态。个人熟悉感与功能结果需要一起验证，不能把这条主张实现成另一个任务管理器。

具体问题假设是：用户需要反复给 AI 补当前目的、分辨建议与已作决定、纠正旧方向，并把多个输出重新组织成可用成果。Noema 希望减少这类协调负担，同时保留用户形成自己判断的空间。是否高频、是否愿意迁移到独立应用，以及收益是否大于维护成本，仍待对照与实际使用验证。

### 在同一件事上比较产品组织方式

以“持续完成一篇自己的观点文章”为同题样例：

| 可选组织方式 | 用户主要得到什么 | Noema 的取舍 |
| --- | --- | --- |
| 以委托任务和交付物组织 | 完成研究、草稿或其他成果，可在持续项目中迭代与改向；协调成本需实测 | Claude 等是很强的现成选择。Noema 的首个主张若只达到这一层，独立应用理由不足。 |
| 以资料库和知识加工组织 | 搜集、核对、讨论资料并生成多种内容，也能执行官方支持的动作 | Gemini Notebook 等直接覆盖。Noema 不优先重做完整笔记/知识库产品。 |
| 以 agent 团队、项目和目标组织 | 组织多个 agent、持续目标、个人状态与协作内容 | LobeHub 是更贴近当前 Noema 模型的结构反例。Noema 暂不采用“管理 AI 团队”作为主叙事，也不据此断言团队方式对所有人都负担过大。 |
| 以用户与 Noema 对一件事的持续共同推进组织（推荐假设） | 用户可以从模糊目的开始，逐步形成判断；必要工作可委托，目的改变时相应调整后续行动与当前成果 | 将目标澄清、变化承接和可用成果放在同一体验中优先打磨；代价是模型判断、长期状态一致性和交互都更难做好。前两类产品也可能完成同样过程，优势须实测。 |

推荐依据是与“功能服务型个人伙伴”的契合度，以及它能给界面明确的信息对象和注意力依据。不是因为它最容易实现，也不是来自现有 agent/room 架构。若同题对照没有实质减少协调负担，就放弃这项差异化假设，不靠新增术语或更多功能保住它。

### 一条具体使用过程

以下全部是合成情境与期望行为，不是当前应用运行结果；各段也不是必须遵循的固定阶段。

**开始：想法还不成熟。** 用户：“我想写推荐算法怎样影响我的阅读，但没想好自己到底想表达什么。先不要替我写全文。” Noema 不生成一篇完整稿或要求填写项目表，先抓住一个影响方向的问题：“你更想讨论读得越来越相似，还是越来越少主动找书？”随后帮助比较这两种理解；需要查证的主张另列为待核实，不把假设写成事实。

**开始行动：已有足够方向。** 用户：“先看主动选择这条线，整理我给你的两份材料，再试一个开头。” Noema 整理材料、给出处并产出可编辑开头，普通对话里可继续修改。用户不必先配置新 agent、建立工作流或理解运行时；对自己设备以外的行动及外部发布仍按权限边界处理。

**改变判断：新信息推翻了一部分。** 用户：“我把推荐算法说得太绝对了。我更关心如何保留选择余地，别写成批判文章。” Noema 保留仍可用的例子和原文，将旧的单向批判假设标记为已放弃，更新当前问题和开头，停止尚未执行的旧方向工作。已经发生的外部动作另行说明，不能假称撤回。用户能看到“保留了什么、改了什么、还有什么未确定”，无需逐条寻找所有旧输出再纠正。

**暂停：这段交流只需聊天。** 用户：“今天不写了，我只想聊聊为什么最近读不进去。” Noema 留下文章当前状态，把注意力转到当下对话；不自动排新任务、不把情绪转成工作指标。是否继续文章由之后的意图决定。

**回来：接着某一部分。** 用户：“继续那篇文章，今天只改开头。” Noema 打开最新稿及仍有效的写作方向，说明需要用户参与的关键选择，直接改当前稿，不另生一份互相竞争的“最终版”。是否需要回顾由当前任务决定，不强制每次展示长摘要。

**带走：成果可独立使用。** 用户能导出文章及所需来源，结束这件事，之后仍可与 Noema 普通聊天。文章、资料和共同经历可以保留，不能因结束事项就失去原始对话，也不自动转为永久人格或技能。

这个例子的判断标准是目的变化后实际工作与成果是否同步、用户是否少做了协调，同时能形成自己的观点。不是 Noema 能不能记住一句偏好，或能不能展示一张状态卡。

### 从行为推导界面和品牌

需要清楚区分三个信息对象：按时间发生的交流、这件事目前有效的理解、可编辑和带走的成果。它们不必永久各占一栏；一段话也不自动成为“已确认决定”。用户能直接修改当前理解或通过聊天纠正，并知道变化会影响哪些后续工作。

- **聊的时候**，对话是主区，身份识别紧凑，当前相关的事可达；不让任务面板占据普通聊天，也不大面积陈列角色。
- **对照资料的时候**，来源与正在讨论的内容能同时看到；引用可定位到原文，假设与资料有区别。重要密度来自减少来回切换，不能用小字号和堆面板伪装。
- **改成果的时候**，当前文稿或其他成果占主区，对话帮助定位改动；能比较变化、回看依据。改完可以留在内容里，不必跳回聊天寻找文件。
- **有几件事并行时**，能快速找到当前成果、等待自己决定的部分和已暂停的事；保留成熟列表/搜索惯例，不因为旧模板失败就禁止常规控件。具体导航形式需随使用验证。

暂定设计哲学是让思考清楚、判断有据、推进有度：界面给问题、内容和动作以足够地位；Noema 的语言能提出理由、承认未定，也会在足够明确时去做事。文艺与哲学气质作为对待内容和人的方式体现，不能机械等同于衬线字体、纸张材质或复古配色。视觉表达仍需独立设计，本提案不选定下一版皮肤。

### 必需能力、删减与架构后果

若用户选择验证该方向，最低完整切片需要：普通交流；为明确要持续推进的事保留当前目的、有效判断、关联资料和成果；在用户改变意图时实际更新相依工作；编辑、导出并重新进入成果；暂停、失败和恢复可控。记忆、工具和任务执行服务于这些行为，不各自变成一个先行系统或前台管理中心。

现有 room/message、停止/重试、引用及任务事件可评估复用。新增的长期状态须由 Noema 管理并保留来源与版本，模型给出的更新不能冒充用户决定，模型说“已完成”不能充当文件或动作完成证据；不把全部历史送进每轮上下文。当前单纯近期消息窗口与目录任务入口不能直接证明上述闭环成立。

优先删减前台强迫用户选择“普通聊天/项目工作”、以专业联系人或 agent 编排组织主要价值的入口、把调试/记忆配置暴露成核心体验的做法。用户确实需要的联系人和群聊仍可存在，不删历史数据，也不因本提案直接覆盖另一开发者的共享实现。工具执行复用成熟 adapter/库；不新造通用工作流平台、记忆引擎、agent 市场或生成 UI 基建。

这会影响长期状态、对话与工作的衔接及成果生命周期，因此需要产品方向反馈、适用 ADR 和数据迁移设计后再进入生产实现。模型能否稳定澄清目的、识别变更影响与调用能力是实际风险；多写规则、加状态表或做漂亮前端都不能替代验证。

### 下一轮怎么证明或推翻

先做最低成本组合反证：用现成 Claude 项目/成果编辑及一份明确的工作说明运行同一情境，确认建议中的行为是否已足够自然。LobeHub 用于核查状态/协作能力，Cherry Studio 用于接入与桌面路径参考，不要求为了凑数量重复完整测试。对照后仍存在具体负担，才实现相应 Noema 切片；不能为验证卖点先造一套复杂系统。

使用同一组素材、同一使用要求，尽可能控制模型与工具能力，不能控制的差异明确记录。用户在开始、修正、暂停、重来时提供同等信息，不故意用坏提示词削弱基线。需要不可推断的目标用户事实或未授权的账户访问时再请求必要输入；没有实机结果前只称候选主张，不称比较优势已成立。

记录用户重复补背景、寻找最新成果、逐条纠正旧方向、整理散落结果的实际操作，以及最终成果质量、错误行动、额外管理负担和回访体验。不预设虚假的改善百分比，也不能以“新增了事项/判断字段”充当成功。合成情境用于功能对照，真实日常使用仍需要目标用户参与。

若成果主要靠用户持续校正才能保持一致，或现成项目＋文档就同样省心，则优先复用外部能力、缩减本方案或重选用途。若用户只需要一次问答/一次委托，Noema 不应强行把它升级为长期事务。方向尚未通过本轮评审，暂不铺开生产重构。

## 可直接改进的基础质量

已保存的数据可恢复且不串房；身份/上下文/能力边界清楚；发送、生成、停止、失败、重试状态真实且可恢复；引用有来源；键盘、焦点、缩放与窄窗可用。这些是质量底线，不是差异化卖点。具体上下文策略仍可重设，但变化必须显式且保留既有数据。

基础质量修复可依据真实缺陷独立推进；它们的检查结果不证明产品定位、自然感或品牌已经成立。真实运行检查覆盖主要、空、加载、失败及恢复状态后，才可报告视觉交付。

## 已撤回的提案

A/B 聊天皮肤原型已删除。“关系延续、情境不混合”及“用户纠正—保存约定—未来带入”均不再作为候选核心体验或待用户批准方案：前者将工程边界升格为叙事，后者将基础记忆/提示词策略重新包装，二者还被错误地放在同一比较层级。保留已有功能不等于保留这些定位主张；本次不据此删除应用数据或源码。撤回依据与后续工作在 Issue #104，旧版本仅作为 Git 历史保留。

## 已结束的视觉方法实验：交谈对象与折面图形

[可操作样稿](prototypes/conversation-study.html)、[桌面截图](prototypes/conversation-study-desktop.jpg)、[窄窗失败状态](prototypes/conversation-study-narrow.jpg)。这是设计方法实验的证据，已退出 Noema 界面候选；用户肯定设计质量，但明确指出气质、密度和角色展示倾向不适配功能服务型个人 agent。旧双栏稿仅留 Git 历史。此稿未进入生产应用，输入仅在页面内存，联系人、消息及回复全部合成。

### 为什么改变构造方法

旧稿在构图前已预设双栏导航壳子，随后以浅色侧栏、大字标、分隔线和留白修饰。删除工程控件并没有形成新的视觉组织；“文字主导”只说明消息排版，不能证明整屏具有辨识度。用户明确否定该结果，本轮不沿其壳子细化，也不先将失败归纳为永久规则。

本轮先确定视觉重心，再安排控件：当前交谈对象占据桌面左侧，聊天成为右侧连续阅读面；列表收进明确标注“聊天”的抽屉，以 Ctrl K 搜索、Alt ↑/↓ 顺序切换补充。原创折面轮廓同时用于大图形、窄窗身份标记和小尺寸应用符号；不同合成身份使用不同轮廓，不混用 Noema 标记。砖红、纸色、硬边阴影和不对称曲面共同构成这一轮的表达。只有模拟回复正在进行时才有轻微图形运动，并尊重减少动效偏好；不借此暗示 agent 情绪、意识或真实在线状态。

这是助手提出的视觉假设，不从 demo 推导独特功能，不代表用户已接受品牌。现有联系人/群聊样例只供检查状态，不构成产品数量或流程规格。此次反馈支持整套改法改善了观感；多个变量同时变化，不能据此断言收起列表、某种颜色或大图形单独造成成功。可迁移的方法是重审过早锁定的结构、让视觉选择相互支持，并分别验证审美质量与产品适配；具体风格不升格为后续模板。

### 取舍与失败条件

大图形占用约三成至四成桌面宽度，列表收起增加一次展开操作。长回复和高频跨会话使用可能更适合常驻列表、较小身份区；这仍是最强替代。窄视口去掉大图形，保留身份轮廓、色面与阅读面的转折。不能把装饰差异或可用性检查当成审美成功；若画面仍只有新鲜外观、长期使用负担明显，需重审这项构图，而非继续换颜色。
