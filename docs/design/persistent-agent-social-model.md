# Noema 持续 agent 与聊天空间：构想和历史边界

状态：2026-10-21 按用户重述修订。旧版将部分助手解释写成“用户确认”，并预设专业范围、邀请审批等细节，表述过强；不再作为当前要求。旧版完整内容保留在 Git 历史。[产品章程](../PRODUCT_CHARTER.md)规定当前产品边界，[产品与界面基线](chat-redesign-brief.md)说明当前探索范围，[ADR 0015](../decisions/0015-agent-friends-and-conversation-rooms.md)记录首轮架构取舍。

## 用户重述的初步构想

Noema 是用户持续交流的核心个人 agent。它通常将较复杂的事交给适合的其他 agent，没有匹配对象时可以创建，复杂事情可以组织多个 agent 协作；简单需求可以自己处理。这是初步想法，不是全部功能清单或固定流程。

其他 agent 也有跨事项经历与发展路径。例如先承担新闻观察，之后参与工具项目的研究；随着经历积累，名字、定位、记忆和经验可能变化。这个例子说明角色不必在出生时固定，不要求每次任务后改名，也不把所有 agent 限定成一个职业。

通信应用是交互习惯参考，Noema 不做 AI 酒馆或以编程为重心的产品。个人伙伴体验、功能服务与协作可以共同成立；它们还需要补齐日常使用、质量把关、失败恢复和长期相处的设计。

## 当前助手判断，尚不是生产机制

- 持续身份与一次执行实例不同。模型、harness、工具或 session 可替换，不应单独决定身份是否延续；并非每个临时 worker 都需要永久联系人身份。
- 委派应权衡任务性质、可并行性、能力、背景损失和成本。“没有匹配就新建”需比较临时执行、现有 agent 接任和长期新建，不一律要求用户审批，也不无条件建档。
- Noema 承担问题判断、组织、结果核对和变化承接；只转交任务及原样汇报会把质量责任留给用户。需要什么核验手段须随具体工作设计，不能用审查模型的同意冒充独立证据。
- 一次经历可以提供方法改进的线索，是否可迁移要看之后不同工作中的表现。稳定身份、当前角色、能力证据、自我描述和名字分别判断；成长不自动扩大权限。
- 普通聊天、一次性需求、暂停和直接联系其他 agent 都可以有价值，不应被长期项目或成长流程吞掉。

这些判断用于下一轮研究与行为验证，不意味着已接受自动学习、自动更名、固定组织结构或数据库方案。详细反证与下一步只在简报和当前 Issue 维护，避免再建重复方案。

## 首轮实现取舍与不变量

ADR 0015 曾选择稳定 agent 身份、独立私聊/群聊与 runtime 分离；它是首轮实现的依据，不是用户完整产品规格。不同房间的历史默认不全量合并；来源、当前请求可用范围与最终披露边界需要区分。跨房间使用的具体权限与检索方式仍可重审，不能因同一身份就无差别注入所有历史。

房间经历、用户偏好、可复用工作方法和能力变化不是同一个 memory 动作。保留可追溯来源，不把一次成功、用户一句反馈或模型自评直接提升成永久规则。旧数据和执行结果保留归属与迁移路径；本次文档修订不删除数据或改写实现。
