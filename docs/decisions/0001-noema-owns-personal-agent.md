# ADR 0001：Noema 拥有个人 agent 的连续性

- 状态：已接受
- 日期：2026-10-12
- 决策依据：用户明确确认 Noema 是独立项目/个人 agent，不是 DSH 插件或某个 agent 应用的外壳。

## 背景

Noema 的长期目标是成为用户自己的个人 agent，而不是某个执行 agent 的壳或单纯任务路由器。用户使用多个模型、应用和专业 agent；其用户模型、经历与能力不应因更换某个执行环境而重置。

## 决定

Noema 是独立桌面应用，并拥有自己的用户侧 agent 身份和可持续状态。外部模型、应用、agent 和 skill 都是可替换或可接入的能力来源。Noema 与用户的持续交流是产品主入口；任务委派是可选行为。

## 为什么不采用其他选择

- 将 Noema 实现为 DSH 插件：令独立产品依赖特定 harness，违背用户已确定的独立项目边界。
- 只向 Codex/Claude Code 安装 skill：能增强一个宿主，却不能成为跨宿主的 owner，也不能保证独立的日常入口与连续状态。
- 只做统一任务派发器：把 Noema 收缩为执行协调，无法承载其个人 agent 身份、日常经历和能力成长。
- 重造所有执行 harness：成本高、重复度大；不构成 Noema 的核心价值。

## 后果

Noema 必须有独立的本地状态、数据迁移、连接管理和用户界面。与外部 agent 的集成必须定义清晰的能力边界，不假设它们共享完整 transcript 或内部记忆。

## 重审触发条件

若长期使用证明用户只需要单一 harness 内的增强，而不需要跨工具连续性，应重新评估独立应用的必要性；若某个平台正式提供可移植、用户可控的 agent 身份/记忆/能力层，也应比较替代成本。
