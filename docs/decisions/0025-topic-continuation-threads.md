# ADR 0025：用主题线程承接跨日个人事项

- 状态：已接受为可撤回的产品与架构切片（助手在用户委托范围内决定）
- 日期：2026-10-21
- 关联：Issue #104；ADR 0015、0016、0020

## 问题

Noema 的普通聊天既要承接即时交流，也会遇到跨日持续推进的目标。把所有更新留在一条长时间线，用户难以回访且主题进展会淹没日常交流；保存一条消息只能帮用户重看原话，不能提供独立的后续对话上下文。工程项目任务则绑定 workspace、runtime 和核验状态，不适合充当研究、计划、学习和创作的通用事项容器。

## 决定

1. **短期交流留在原聊天。** 普通问答、追问和临时搁置不自动拆分。仅当存在跨日的连续目标，且分开能减少干扰或改善回访时，Noema 可说明收益并提议主题线程；用户接受后创建。用户明确要求另开一条持续讨论时直接执行。
2. **线程仍是 Noema 聊天。** 同一个 `noema` identity 在一个来源私聊下可有多个子聊天；线程自己的 transcript 是后续交流的事实来源。它不是新 agent、group、工程 workspace、提醒或项目板，不创建通用 `matter` 表。
3. **来源由用户显式选择并可见。** 从一条或多条已完成的源消息创建线程，将不可变内容快照作为首条可见转发卡片保存，并记录源 room/message ID 以供回跳。该消息参加线程上下文；源 room 的其余历史不隐式加载。
4. **Noema 本机社交存储拥有来源关系和生命周期。** 在 `social_rooms` 增加可空父 room、来源消息与关闭时间；普通房间这些字段为空。线程创建和首条来源卡片在同一事务中写入。现有聊天消息仍是用户交流记录，不新增模型总结调用、状态摘要或任务 worker。
5. **关闭可逆。** 活动线程可关闭以离开当前活跃列表；关闭后禁止发送、转发或启动项目工作。用户可从历史重新打开。删除线程只删除其自身记录与关联工作；删除源房间时通过外键级联删除其子线程。初版提供明确的线程删除操作。
6. **长上下文保留来源锚点。** 普通聊天每轮最多传递最近 40 条消息。主题线程的来源引用即使超出该窗口，也须继续作为明确、可见的锚点参与上下文；这不代表注入来源房间的其他记录。之后的长线程仍遵循既有有限窗口，不生成自动摘要。
7. **只在主聊天中创建第一版线程。** 只接受 `noema` 单人 direct room 作为来源，线程仅含用户和 Noema；specialist 与 group 后续如有真实需要再设计。创建线程不调用模型、不触发外部工具。实际任务/周期性监控另走具有明确权限、成本与失败语义的能力。

## 替代方案

- **所有事情都留在原房间：**复用回复引用与最近 40 条上下文，简单而熟悉；不能把多个多日目标与普通聊天隔开，也缺少回访锚点。
- **只增加收藏/稍后看：**能找回原消息，但持续对话仍在同一时间线，且需另建收藏状态与列表；不是当前候选所需的独立脉络。
- **通用事项对象/计划台：**为状态、目标、更新和成果引入新的生命周期，增加维护与重复记录；当前聊天线程即可拥有后续对话，不支持先建这套对象。
- **静默跨 room 检索历史：**没有清晰来源与上下文授权，拒绝。线程只使用可见引用快照。

## 后果与重审条件

- 数据库仍以 `social_rooms` 与 `social_messages` 为唯一聊天状态来源。父/来源关联只是线程的最小拓扑，不是平行事项生命周期。
- 搜索当前只匹配聊天标题、成员和最新预览；线程标题需在创建时由用户提供/确认，并可经现有聊天名编辑路径找到。消息全文搜索仍是独立改进，不得假称已支持。
- 来源快照会复制用户选择的消息内容；它保证线程可独立理解，但增加一份本地数据。删除源房间时删除所有子线程，删除线程不影响父房间。
- 如果实际使用中线程创建频繁、引用卡无法提供足够上下文、侧栏难以表达从属关系，或用户经常混用线程与提醒，应重审触发边界和结构；不能靠新增更多状态面板补救。
- 若未来要定时监控、后台推进、自动创建协作者或成果核验，须单独审查其运行时间、授权、失败、成本与停止路径；本 ADR 不授予这些行为。
