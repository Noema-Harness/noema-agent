# ADR 0026：以 Noema 主聊承载理解与按需行动

- 状态：接受为当前产品与架构基线（用户于 2026-10-21 选择推荐结构）
- 日期：2026-10-21
- 关联：Issue #104；ADR 0015、0016、0019、0025

## 问题

当前主界面把 Noema 和专业联系人并列，要求用户逐轮选择回应者；项目工作还需先切换模式、选择工程联系人并提交。旧 `RootAgent` 则有另一条单聊和有限的 DSH 代码委派路径。用户需要先理解 Noema 内部的 agent 和模式，才能把一个事情交出去。这与用户选择的方向冲突：用户先和同一个 Noema 交流，由 Noema 理解事情，再按需组织能力。

日常聊天、共同思考、一般计划和创作不需要因为 agent 能力存在就变成任务。反过来，真实异步执行涉及执行者、文件范围、运行状态和核验，也不能完全隐藏在一次模型回复里。

## 决定

1. **Noema 私聊是默认个人 agent 入口。** 普通交流、探索、写作和一般计划继续是当前 room 中的对话。Noema 决定直接回应或使用当前实际可用的能力；用户不应为了每一轮先选择回应 agent 或“聊天/执行”模式。
2. **只有真实行动才产生执行状态。** 当用户明确要求采取一个已有能力支持的行动时，Noema 可在当前聊天中路由到该能力。异步执行记录关联来源 room，并在原请求附近显示真实执行者、范围、状态、失败/停止和独立核验结果。不得用合成进度消息替代真实状态，也不得把一次委派伪装成新联系人或新聊天。
3. **普通话语不授予未实现能力或额外权限。** 现阶段仅接入既有 DSH 项目工作能力；普通讨论、含糊想法和未实现的研究/监控/外部行动不启动后台操作。启动文件工作前仍须选择具体工作区并看到现有数据流与 Windows 执行限制说明；每个 workspace 同时最多运行一项写任务。停止不承诺回滚已写入内容。
4. **复用社交 room 与项目工作生命周期。** `SocialChatStore` 是当前用户聊天的权威存储，`SocialWorkService` / `social_work_tasks` 仍是文件执行能力的生命周期 owner。一次执行的 room 是来源上下文，executor identity 是执行责任归属；新模型不得要求执行者必须先作为可见房间成员，才能由 Noema 内部调用。实现必须保留 server-side 能力、归档、开放 room、workspace 和并发检查。
5. **联系人和群聊保留为显式交流方式。** 用户仍可主动打开专业 agent 私聊或有真实多人交流需要时创建群聊；群聊逐轮回应方式应另行验证，不能由当前按钮布局倒推其长期结构。跨日主题继续遵循 ADR 0025。单次执行不自动创建持久联系人、经历总结或 agent 自我改名；这些机制需要独立证明后续使用收益与状态生命周期。
6. **旧根对话逐步退役，不做破坏性删除。** 新的个人对话与行动不再扩展到单一 root transcript。迁移或移除旧 UI 前，先盘点 captures、Codex 导入、用户互动约定和仍在运行的任务，分别决定迁移、作为独立能力保留或删除，并验证旧消息仍可访问。此 ADR 不授权删除用户数据。

## 替代方案

- **保留逐轮显式路由（ADR 0016/0019 的当前体验）：** 权限动作清楚、改动较少；继续把联系人和模式选择责任交给用户，Noema 仍像多种 agent 聊天的外壳，因此不作默认交互。
- **隐藏所有行动：** 初始页面简洁，但文件副作用、第三方处理、执行者和故障状态不可见，不能支持用户控制和交付把关，因此拒绝。
- **让每种计划、创作和聊天都建成独立任务/agent：** 将把普通对话过度对象化，并过早引入状态、创建与删除生命周期；当前证据不支持，因此拒绝。

## 后果

- 对话成为连续的用户入口；项目执行不再要求用户先理解并切换内部运行模式。
- `SocialChatService` 需要成为 Noema 私聊的运行入口，并以一条可测试的边界调用现有 `SocialWorkService`；工具请求不会直接操作文件，工作区选择与执行限制仍由本机服务执行。
- 项目任务仍为单独持久对象，因为它有并发、停止、核验和跨进程生命周期；它不是通用待办或事项表。
- 已有两个聊天存储/执行路径和旧 root 状态需要逐步收敛；迁移期间允许兼容读取，但不能再为新功能建立第三条路径。
- 首轮能力仍是代码工作，不能据此宣称 Noema 的整体卖点是编程或委派。下一步设计须覆盖普通交流、思考、计划、创作和协作，再定义完整视觉语言。

## 重审条件

真实使用表明 Noema 经常误把讨论当成行动、用户无法理解或撤销执行、目录选择成本高于收益、任务状态打断普通聊天，或 agent 路由持续需要用户手动修正时，重审工具触发、确认边界与界面表达。新增第二种长期能力前，单独评估其 owner、来源、成本、权限、失败和删除路径，不默认建立通用插件或任务框架。
