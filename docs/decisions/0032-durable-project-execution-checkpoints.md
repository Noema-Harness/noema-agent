# ADR 0032：项目执行检查点与工具结果持久化

- 日期：2026-10-24
- 状态：按委托范围由助手决定并实现
- 关联：#112、ADR 0016

项目执行跨越多次模型请求与本地工具动作。只保存工具名称和终态，无法在进程重启后还原模型所需的上下文，也无法解释一次工作停在何处。每个任务因此保留有界的运行消息检查点，以及工具步骤的参数、结果、输出和副作用状态；执行意图先于文件写入或命令启动持久化，完成后再保存结果。

检查点与任务使用同一 SQLite 生命周期，并随任务删除级联清理。消息快照上限为 1 MB；超过上限时停止该轮并保留既有任务状态，不裁掉上下文后继续造成错误续接。检查点包含本地任务提示、模型工具参数及工具输出，因此延长这些数据在本机数据库中的留存时间；当前沿用 Noema 已有本地数据库保护方式，不把检查点发送到其他服务。工作区内容与命令输出仍可能包含敏感资料，用户选择工作区时已有的数据流提示继续适用。

应用重启时，未完成任务仍标为中断。工具调用意图若没有已保存结果，其副作用为未知，不能自动重放；检查点提供审计与后续安全恢复所需的事实，但本 ADR 不授权启动时自动调用模型。显式恢复流程须先校验未决步骤及工作区身份，并只在不存在未知副作用时继续；未知步骤应要求重新核对或由用户另行决定。

参考固定版本 OpenCode `d93568f3344e1a93297d56bc1dc71892104856d0` 的 durable execution claim、工具步骤和恢复预算设计。Noema 复用其中“意图持久化早于执行、结果用于恢复判定”的边界，不复制其服务端自动 at-least-once 恢复：本地工具可能运行用户命令并修改文件，自动重放并不安全。

重审条件：运行记录大小持续影响数据库、工具结果需按类型脱敏/清理、或显式恢复 UI 开始实现。此时保持任务为唯一生命周期 owner，不建立第二套执行历史。
