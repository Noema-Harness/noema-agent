# ADR 0014：逐轮互动约定门控候选

- 状态：不采纳为产品行为；原型已移除，保留为可重审的设计候选
- 日期：2026-10-17
- 决策者：助手，在用户委托的 Noema 生命周期内
- 关联：Issue #2 / M1；ADR 0006、0008、0011

## 问题

Noema 当前把同一 surface 的有效互动约定放进每轮上下文，再要求回答模型自行判断何时适用。RPEval 的 `Ignore / Support / Dominate` 分类提示了门控候选，但它的公开偏好样本不能直接证明 Noema 的明确互动纠正需要另加一次模型调用。

## 外部证据与范围

- OP-Bench 将过度个性化拆成无关引用、迎合和重复；论文报告记忆增强方法在其合成英文单轮基准上低于无记忆基线。但这些画像记忆不等同于 Noema 的用户明确纠正。[论文](https://arxiv.org/abs/2601.13722)
- RPEval（2026 预印本）提出 `Ignore / Support / Dominate` 与意图推断，但不证明它能迁移到 Noema 的互动约定或提升自然对话。[论文](https://arxiv.org/abs/2601.16621)
- RPEval 数据为 CC BY-NC 4.0，仅用于本机个人评估；数据与逐条结果留在 D 盘，不进入仓库或发行包。[许可](https://github.com/XueyangFeng/RPEval/blob/main/LICENSE)

## 实际评估与结论

- 一次隔离合成对话中，gate 将情境相关约定判为 `dominate`、编码约定判为 `ignore`，约 2 秒返回；随后最终回答收到 FreeLLMAPI `provider_unavailable`。这只证明请求和过滤链路曾运行，不证明整轮体验可用。
- 9 条分层样本的基线/gate 配对仅 2 组完整；基线 1/2 正确、gate 2/2 正确，但两组中一组路由相同、一组路由不同，不能据此归因。其余被上游不可用和限流截断。紧接着固定 Nemotron 重跑 0/9 完成，处于同一短时额度窗口，不能视为模型质量比较。
- 获准的一次 Kilo 直连请求成功，但把一条标为 `ignore` 的样本判成 `support`。FreeLLMAPI 官方平台表说明 Kilo 匿名免费路由有限额，且提示/输出可能用于训练；免费不代表无限额度或隐私保障。[官方文档](https://github.com/tashfeenahmed/freellmapi/blob/main/docs/en/providers/01-supported-platforms.md)

结论是**未判定**：证据不足以证明门控有效，也不足以证伪。请求密度可能消耗免费额度，构成评估混杂；额外调用则是明确的延迟和失败面。因此不把门控加入默认客户端，也不保留测试专用实现。当前应用继续使用原有上下文组装，不新增记忆类型或状态。

## 重审条件

只有当额度恢复后能以低速率、同一路由完成可重复的配对比较，且稳定改善 `ignore` / `dominate`、未明显损害 `support`，再重新考虑实现。若无法获得可控路由，或增益不足以抵偿额外调用，则关闭此候选，不继续堆叠 prompt 或记忆机制。任何复测都不得使用真实用户历史。
