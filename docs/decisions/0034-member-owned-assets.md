# ADR 0034：成员自有资产的版本化存储与装载

- 状态：第一阶段本地实现；自动项目成长流程尚未交付
- 日期：2026-10-26
- 关联：Issue [#103](https://github.com/c3115644151/noema-agent/issues/103)、[#109](https://github.com/c3115644151/noema-agent/issues/109)、ADR 0029

## 问题

长期成员需要积累可复用的身份说明、工作原则、记忆、经历和技能；这些内容必须属于成员本身，不与 Noema 或其他成员共享。普通聊天和项目文件权限不能因为成员新增资产而改变。资产还需要说明来源，并能恢复到旧版本，避免一次未验证的经历永久改变后续行为。

## 决定

1. 首阶段复用 Noema 已有的 SQLite 持久层，以成员 ID 和受限相对路径隔离资产；不为每位成员另建可执行的 OS 工作目录或引入新服务。SocialChatStore 是当前权威存储。将来若需要文件互操作，可在此边界上增加导出/导入，不迁移模型权限语义。
2. 每次写入、删除或恢复都追加不可变修订，保留修改理由、来源会话轮次和可选项目 ID。删除以 tombstone 表示；恢复会创建新修订而不是覆盖旧记录。相同成员、路径和来源轮次的重复操作幂等，防止一次回复重试重复沉淀。
3. 成员只能维护自己的资产。受支持路径为 `identity.md`、`instructions.md`、`memory.md`、`experiences/<slug>.md` 和 `skills/<slug>/SKILL.md`。应用限制单文件、总容量及资产数量；并发修改使用期望版本号拒绝覆盖。
4. 每轮读取当前成员的身份、指令和记忆；注入前有总字符预算。技能仅注入受限名称/描述索引，完整内容按需读取。经历档案默认不注入。资产作为成员自有参考资料提供，不能覆盖系统约束或扩展工具权限。
5. 资产管理工具仅对专业成员开放，并仅在用户要求复盘/维护、或当前请求明确指向成员资产时加入本轮工具列表。Noema 不能借此写入其他成员资产。小任务不应自动触发成长调用。

## 取舍

- **真实文件夹：** 更接近 OpenCode 的文件型 skill 目录，便于外部编辑；但当前会把 agent 资产直接暴露给命令执行器，增加路径安全、文件监听、并发、备份和原子回滚问题。Noema 必须拥有资产的身份范围与版本生命周期，因此当前以数据库作为可替换边界。
- **仅在 system_prompt 字段追加文本：** 改动少，但不能清晰区分身份、技能、经历和记忆，也不能按需加载、追踪来源或恢复旧版本。
- **完整资产平台：** 暂不引入文件浏览器、通用插件注册或自动化晋升流程；当前只接通成员对自己文本资产的读写闭环。

## 已知缺口与重审条件

当前尚未实现项目结束时的自动成长触发、跨成员项目经历简报、Noema 评议和成长完成后的项目归档。这些必须与 #113 的项目生命周期和 #103 的来源链衔接；不得把显式资产工具误称为自动成长闭环。还没有成员资产专用 UI。若真实使用需要在外部编辑、资产量超过当前边界，或数据库快照难以满足导出/恢复要求，再评估文件工作区或文件型技能加载器。
