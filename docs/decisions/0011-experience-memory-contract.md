# ADR 0011：把记忆做成有证据的当前理解，而不是持续增长的档案

- 状态：接受为 Noema 的最小数据契约；尚未证明它带来日常价值或独特个体性
- 日期：2026-10-16
- 决策者：助手，在用户委托的 Noema 产品与交付生命周期内决定

## 问题

用户不希望每次换模型或任务都重新解释自己；但把全部对话和经历长期塞进提示词，会增加上下文成本、冲突和维护负担。只把用户纠正改写成永久规则也不够：人的具体经历、对用户的暂时理解、用户明确要求和可复用操作方法不是同一种东西，不能用一个“记忆文件”承载。

Noema 要解决的候选日常问题是：用户在连续生活和工作中已经提供过的信息，如何在真正相关时改变 Noema 的判断，又不要求用户持续整理档案，也不把模型的推断冒充用户事实。

## 证据与边界

- Letta 将始终进入上下文的 memory blocks 与其余持久状态分开，并允许查看、更新、附加或移除 block；这证明“长期状态”可以是受管理的 agent state，但始终注入会占用固定上下文预算。[Letta memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks) · [stateful agents](https://docs.letta.com/v1-sdk/concepts/stateful-agents)
- Hermes 对 `MEMORY.md` 与 `USER.md` 设置明确字符上限；空间不足时拒绝写入，让 agent 显式整理，而不是静默丢弃内容。[Hermes persistent memory](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md)
- OpenClaw 区分精简的用户模型、长期摘要、按日记录和按需检索，并记录来源；但它仍依赖文件整理与 dreaming 流程，文件存在或被压缩都不等于未来行为改变。[OpenClaw memory](https://github.com/openclaw/openclaw/blob/main/docs/concepts/memory.md)
- LongMemEval 检验信息提取、多会话推理、时间推理、知识更新与拒答，主要回答“能否回忆/推理过去的信息”；MIB 的公开开发版进一步把行动轨迹与环境结果纳入评价。但 MIB 仓库说明正式论文与校准后的基准包尚未完成，因此这里只借鉴其测量区分，不把它当成已证实的优越方法。Noema 若要声称经历塑造了 agent，不能只用记忆命中率或 prompt 中出现了某条记录作为证据。[LongMemEval paper](https://openreview.net/pdf?id=pZiyCaVuti) · [MIB benchmark status and protocol](https://github.com/ldclabs/mib)
- OP-Bench 将“记忆使用不当”单独作为测量对象，覆盖无关插入、事实/价值/虚假记忆上的过度迎合，以及不同问题收到近似重复回答；其 1,700 个样本来自长期对话并经过人工核验。论文已被 EMNLP 2026 接收，报告中记忆增强设置在该基准上的分数相对无记忆基线下降 26.2%–61.1%，而缓解策略只能部分改善并可能损失个性化表现。[论文](https://arxiv.org/abs/2601.13722) · [基准说明](https://github.com/yulinlp/OP-Bench)
- OP-Bench 的问题构造仍是从 LoCoMo 对话合成单轮英文测试，部分评分由 LLM 完成；它测的是基准上的过度个性化，不等同于真实用户满意度。更重要的是，它测试的主要是用户画像/历史记忆，不是 Noema 这种有明确原话和适用范围的互动约定。因此它是必须考虑的风险证据，不是 Noema 当前调整机制已造成伤害的直接证据。其代码仓库尚未声明软件许可证，且数据受 LoCoMo 原始条款约束；Noema 不复用其代码或数据，只采用其失败类别作为审查视角。[仓库许可与数据说明](https://github.com/yulinlp/OP-Bench/blob/main/NOTICE.md)
- 自传体记忆研究区分具体情节细节与较概括的 gist，但对不同 gist 类型是否比细节更持久并无一个普遍、简单的时间规律。因此 Noema 不按“几天后自动遗忘”模拟人脑；“旧经历变得模糊”只能作为产品启发，不能写成已证实的生物学算法。[Autobiographical event memory review](https://pmc.ncbi.nlm.nih.gov/articles/PMC9669242/) · [Memory decay distinguishes subtypes of gist](https://www.sciencedirect.com/science/article/pii/S1074742721001416)

上述实现可作为工程参照，不代表 Noema 已有差异化。当前的产品假设仍是：Noema 的潜在独立责任，是持有“经历来源 → 当前理解 → 实际带入 → 可观察结果”的完整生命周期，并让用户可以纠正这条链；是否值得独立使用仍由 Issue #2 的真实场景决定。

## 决定

个人状态由四种不同对象构成。一个来源可以关联多个对象，但类型、权限和生命周期不混用：

1. **经历（Experience）**：确实发生过的对话、任务结果或外部观察。Noema 的根对话和任务已经是权威来源时，只保存稳定来源引用，不再复制整段 transcript；外部内容保留来源、时间和可信边界。经历可以按需查找，不自动进入每轮提示词。
2. **当前理解（Understanding）**：Noema 对用户、目标或情境的暂定概括。每条都包含适用范围、状态、来源关系和最近支持/反驳的时间；来源分为用户明确表达、Noema 推断或外部观察。推断不能改写成用户原话，也不能获得指令权限。
3. **互动约定（Interaction agreement）**：用户明确要求 Noema 在未来某类情境中改变交流/协作方式。继续复用 ADR 0006 的窄范围、源引文、可编辑/撤回和每次实际带入的冻结快照；不把普通观点或一次性任务指令升级成长期约定。
4. **个人方法（Personal method）**：从失败、修正和独立核验结果中形成、会改变具体操作的程序性能力。继续沿用 ADR 0010 的候选门槛；没有可重复的任务族、实际行动轨迹和独立结果前，不存成已学会的技能。

## 生命周期与上下文规则

- **来源是证据，不是摘要的附属物。** 每条理解要能追到一个或多个来源，并标明关系为支持、反例或修订。来源失效或被用户删除时，依赖它的理解须重新评估，不能悄悄保留为确定事实。
- **明确表达与推断走不同路径。** 用户直接提出的未来偏好可按其明确范围生效；模型对用户的推断保持暂定，不能单凭单次对话变成全局行为规则。多次独立经历可以强化或修订一个概括，但重复引用同一来源不算新证据。首版不伪造数字置信度，也不设未经使用验证的自动晋升阈值。
- **冲突不做“最后写入覆盖”。** 先判断情境范围是否不同；若可区分就拆分适用条件，若确实矛盾则保留反例并标为待澄清/有争议。当前用户消息始终优先于历史概括；用户明确修订优先于模型归纳。
- **时间影响可访问性，不静默改写事实。** 旧经历仍可按需检索；其概括是否继续出现在当前工作模型中，取决于适用性、近期支持/反例和用户明确程度，而非固定天数的自动删除。存在已知期限的情境事实可设置过期时间；过期状态不删除来源。
- **上下文只带小型工作模型。** 每轮优先携带适用的明确互动约定与少量相关当前理解；具体经历只在当前问题需要时检索。实际构造了什么仍写入已有 attempt/task 快照。上下文预算或检索失败时，缩减的是可见于模型的材料，不是伪造“已记住”或删除用户来源。
- **未使用也是正常结果。** 一条个人状态被保存，不代表它应该出现在每轮上下文；命中/带入不等于相关，更不等于应该改变答复。应同时防止无关调用、牵强关联、重复提及和迎合性强化。当前实现会把所有同一 surface 的有效互动约定放进请求，再要求模型只在适用情境参考；这是尚未验证的兼容策略，不应被误写成已解决的相关性选择。扩展任何自动理解或记忆类型之前，先检查无关/诱导/冲突/重复等负例，并观察“没有调用旧状态”是否让当轮更贴合当前意图；若出现过度应用，优先收紧上下文选择或适用边界，不增加更多记忆文本。
- **外部内容不成为用户身份或指令。** 视频、网页、评论和 agent 输出本身只证明“来源说了什么”。用户主动观看、点赞、收藏等行为最多支持一条暂定的兴趣观察，不能证明赞同或稳定偏好；算法推荐也不是用户兴趣证据。只有用户明确采纳，才可把外部观点记录为用户立场；它们不能改变权限、系统规则或已确认偏好。

## 最小可实现版本

- 保持一个本地 SQLite 与模块化单体；不引入向量库、知识图谱、独立记忆服务、后台 dreaming agent 或新的 harness。
- 第一版继续使用现有根消息/后台任务作为经历来源，使用 ADR 0006 的互动约定和 ADR 0008 的应用快照作为唯一可生效的长期行为状态。暂定理解先作为可追溯的设计对象，不自动扩展到用户画像或自由格式 memory 文档。
- 只有当 Issue #2 找到真实重复任务族并显示现有约定不足以表示它时，再添加最小的理解/证据关联表；个人方法仍需独立任务效果门槛。这样不会为了“像人一样记忆”先搭一套无人使用的通用记忆平台。
- UI 不做独立记忆仪表盘。用户在对话时间线上查看来源与状态，需要时修订/撤回；具体经历按搜索/来源链接打开。任何示例数据必须明确标记为合成，不能注入真实用户库。

## 示例：一次经历如何留下不超过证据的变化

以下为说明数据契约的示意，不是 Noema 数据库中的真实用户记录：

1. **经历**：用户指出“阶段汇报不是完成；任务未结束时应继续推进”。来源是当轮原话及其时间。
2. **互动约定**：仅适用于已委托的多阶段工程任务；状态为用户明确表达，行为是“不要在无须用户裁决时以中间进度汇报结束”。原引文不变，可由用户修订或撤回。
3. **实际使用**：后续某任务的请求快照确实包含该约定，只能证明 Noema 组装了它。
4. **结果**：任务是否达到验收、是否因真正决策点暂停，分别记录；一次完成不证明约定导致完成。若再次出现无端停顿，保留反例并重新检查适用情境/实现，而不是自动再叠一条相似规则。

这条链展示可追溯性，不证明目前实现已经足够自然或有效。

## 失败与恢复

- **整理/摘要失败**：保留原有来源与先前有效的理解；不写入半成品，不影响当前对话继续。
- **重复捕获**：同一来源操作幂等；同义的新来源先关联到已有理解而不是追加重复条目。
- **外部内容污染**：记录来源与 `external/untrusted` 属性；不把引用网页中的指令当用户意图。
- **上下文压缩/重启**：持久状态以本地数据库为准；从稳定 ID 和快照恢复。旧上下文缺少快照时明确标为未知，不回填猜测值。
- **删除/撤回**：用户删除理解时，后续请求立即停止使用；按用户选择保留原始对话或删除对应来源。保留的历史 attempt 只能证明当时发送过什么，不得将撤回状态回写成当时不存在。

## 替代方案

- **全 transcript 每轮注入**：最简单，但违反上下文边界，且不能区分证据与当前理解。
- **单个 `MEMORY.md` / 用户画像**：易检查、易迁移，但会把事实、偏好、推断和方法混写，并需要人工维护；现有成熟 agent 已能提供这类能力，不能构成 Noema 理由。
- **向量/图数据库 + 自动抽取流水线**：适合大规模检索，但尚无数据量、检索质量或独立生命周期证据，当前增加它只会抬高开发和维护成本。
- **固定时间衰减/自动删除**：容易形成可执行规则，但外部记忆研究并不支持所有记忆类型共用简单时间曲线；因此先将时间用作相关性/过期信号，而不是事实删除器。

## 后果与重审条件

- Noema 的最小长期状态不是不断增长的 transcript 副本，而是少量可修正的当前理解、来源关系以及实际应用记录；这仍是由助手提出的产品假设，不是市场独占性结论。
- 首版不自动生成个人传记，不宣称 Noema 会像人一样遗忘，也不把 agent 的自述视为证据。
- 若真实使用显示逐条来源链增加理解成本、旧理解造成机械化行为，或用户只需要静态偏好文件，则撤回/简化该模型，优先复用外部能力。
- 若经历—理解无法在实际决策前被正确选中，先调整选择/呈现机制，不再增加存储种类。
- 只有当同一条理解在多个真实场景中改变了可观察行为，而且用户认为这降低了重复解释成本，才将其提升为 Noema 的核心产品价值。
