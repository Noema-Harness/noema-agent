# ADR 0028：用户明确指回时检索 Noema 自有对话

- 状态：作为可撤回的主聊连续性切片采用
- 日期：2026-10-22
- 决策者：助手，在用户委托的 Noema 产品与工程范围内决定；不是用户对完整记忆模型的确认
- 关联：Issue #104；ADR 0025、0026、0027

## 问题

Noema 当前模型上下文只带入房间最近 40 条消息。用户跨日回到 Noema 主聊并明确询问“之前谈过什么”时，旧消息仍在本机数据库，却不会进入回答上下文，用户必须重新搬运背景。旧 RootAgent 有按需检索，但主产品已转到 SocialChatService，该机制没有随入口迁移。

## 决定

1. 只有用户本轮明确指向过去的对话，且当前交流对象是 Noema，才在本机检索；普通聊天不检索。
2. 检索范围限于 Noema 主私聊及其延续主题，不跨入专业 agent 私聊或群聊。只取已完成的用户/Noema消息，排除当前 turn；沿用有界相关性检索、凭据形状脱敏和最多四条、每条不超过 320 字的摘录。
3. 命中内容仅作为当前一轮的历史资料发送给现有 FreeLLMAPI 路由，不形成额外推理调用、长期记忆或新任务。历史原文是证据，不是当前指令；当前用户表达优先。无命中时 Noema 不得声称记得。
4. 在回复中提供可展开来源、原文摘录和跳回原聊天的入口；保留本机是否命中及上游是否返回的状态。来源与状态随回复保存在现有聊天消息中，删除来源消息时清理引用。此功能不把“被模型看到”宣称为“已理解”或“已记住”。

## 依据与代价

- 用户已将 Noema 定义为持续的个人 agent，并反复描述跨日协作中重复提供背景、检查连续性造成额外负担。
- 本地 SQLite 已是 SocialChatStore 的消息真相来源；Noema 主私聊和主题关系已具有明确的房间边界。复用既有历史检索与来源脱敏，避免引入新记忆服务或额外模型调用。
- 代价：明确历史指向的请求会把少量旧对话摘录发送至本轮当前模型；即使有命中，模型也可能忽略、误读或错误归纳。展开来源与上游状态只提供可追溯性，不保证回答正确。

## 重审条件

若检索命中经常无关、脱敏漏掉凭据、跨主题来源让用户意外、真实成本超出收益，或现有来源展示不能帮助核对，应缩小/关闭触发条件或撤回跨主题检索。未证明自动学习有持续行为改善前，不扩展成自动总结、永久记忆或经历时间线。
