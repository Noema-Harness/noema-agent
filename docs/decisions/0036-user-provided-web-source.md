# ADR 0036：读取用户提供的网页来源

- 日期：2026-10-27
- 状态：实现中；用户提供链接读取已实现，搜索发现与独立事实核验仍未完成
- 关联：#112、ADR 0005、ADR 0035

## 背景

算术工具只能计算表达式，不能验证数字或前提。来源能力需要留下模型实际可见的证据，同时避免把网页正文当成指令，或把“读过”误说成“已核实”。

## 决定

1. 第一片能力只读取用户当前消息明确提供的 HTTP/HTTPS 链接；本轮最多向工具暴露 3 个候选 URL，工具只能选择其中链接。没有显式链接时，不暴露网页读取工具。
2. 网页正文作为有界外部资料进入本轮模型上下文，与助手对话历史分开；正文不获得指令权限。仅保留可读摘录及来源标题、地址、时间和截断状态，挂到本次助手尝试上。
3. 只接受公开地址上的 HTTP(S) 文本页面，限制端口、重定向、响应体、提取规模与正文长度；每次重定向重新验证地址，连接使用已验证的解析地址。遇到配置了系统代理的透明 DNS 映射时，仅允许 `198.18.0.0/15` 映射用于用户明确提供的域名；代理映射下重定向只能落到用户消息中的域名。私有/保留 IP 直连仍失败关闭。读取失败时说明原因，不伪装成成功来源。
4. 对话界面显示可打开的来源、摘录和截断状态，并区分“已随请求发送”与“是否收到无法确认”。该记录证明 Noema 成功读取并尝试提供资料，不证明模型使用/理解了资料或来源内容正确。
5. 当前实现不提供通用搜索、站点爬取或自动事实核验。不能由 URL 读取推断出 Noema 已具备发现来源的能力；后续搜索接入须基于可维护的提供方接口，并考虑凭据、隐私、费用和失败语义。

## 取舍与复用

- 复用 Mozilla Readability 提取正文，以 `jsdom` 解析，并沿用项目现有 SQLite 对话/尝试生命周期；不新增检索服务或通用引用平台。
- Open WebUI 的成熟实现把工具来源与模型上下文分开，并将来源归属到具体答复；参照其固定版本的 [builtin tools](https://github.com/open-webui/open-webui/blob/33c1978d5bad52a31df75ea55143025dfad18d16/backend/open_webui/tools/builtin.py) 与 [middleware](https://github.com/open-webui/open-webui/blob/33c1978d5bad52a31df75ea55143025dfad18d16/backend/open_webui/utils/middleware.py)。其多提供方搜索生态需要配置，不照搬成无凭据的网页抓取。
- 这片能力适合用户说“读这个链接”。用户只提出一个需要当前事实的问题时，Noema 仍需搜索来源；这一缺口保持显式开放。

## 重审条件

当 Noema 加入搜索提供方时，重新评估多来源检索、摘要归属、模型输出中的来源引用、提供方不可用与隐私/成本控制；在此之前，不宣称一般性事实已核验。
