# ADR 0031：项目评审是主聊中可恢复的请求

- 日期：2026-10-24
- 状态：按已确认反馈流程实施；实现取舍由助手决定
- 关联：#115、ADR 0029

项目等待用户判断时，需要明确的问题、主聊消息锚点和单次响应；普通聊天不能被当成批准。为每个请求保留项目、主聊、Noema 请求消息、问题、状态和反馈消息关联。一个项目最多一个待评请求。请求创建与项目进入等待原子提交，明确反馈与新聊天回合、解除等待原子提交；模型失败后反馈仍在原回合，可原位重试。

沿用现有消息循环及 SQLite，不在内存中挂一个等待用户数日的模型调用。项目页只跳到该请求，不增加第二套反馈入口。现阶段反馈解除等待后由 Noema 回复；完整团队续派属于 #113，不假装已自动派发。

参考 OpenCode `24b5ed8bcc60aa9a20cf4e3edf1444470e0e6464` 的 `packages/core/src/form.ts` 和 `tool/plugin/question.ts`：请求有稳定 ID、会话归属和终态响应校验。其进程内 Deferred/缓存适用于单次工具问答；Noema 跨进程项目评审采用持久请求。拒绝用最新消息或标题关键词猜测评审位置。

重审条件：多个独立问题需要并行评审、交付物版本变更需要作废请求，或调度器有了持久收件箱。此时演进请求状态，不复制一套任务系统。
