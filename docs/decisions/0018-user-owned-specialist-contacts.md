# ADR 0018：让用户创建并管理自己的专业 agent 联系人

- 状态：接受为可撤回的产品切片（助手在用户委托范围内决定）；不是对专业能力或独立产品价值的验证
- 日期：2026-10-18
- 关联：Issue #2、#82；ADR 0015、0017

## 问题

Noema 已有独立的 agent identity / room 模型，但当前可用身份只有源码 seed 的 Noema 和工程搭档。若用户不能创建自己的联系人，“我的 agent”仍是固定 demo roster；也无法检验用户是否愿意把某类长期专业实践交给一个持续身份，而不是临时 prompt 或一次性任务。

## 决定

新增一条本地、显式、可归档的 specialist 联系人创建路径。它创建的是可持续联系的身份，不是一次任务实例，也不声称 profile 字段可以自动制造专家能力。

1. **用户发起并确认创建。** 联系人创建是显式 UI 操作。Noema 不从普通聊天或一句任务需求中静默推断并创建好友；草稿阶段可随时取消，确认后才写入 SQLite。
2. **描述长期实践，不填系统提示词。** 用户提供姓名、长期专业范围和合作方式。界面以简短例子区分“持续研究一类工作”与“一次性待办”。Noema 用稳定模板把这些信息编入现有 `system_prompt`；用户无需理解或维护 prompt 结构。
3. **身份与能力分开。** 新联系人使用稳定 `social_agents.id`，初始只有普通对话能力；不获得 DSH/Codex、项目读写或 MCP/action capability。未来增加能力必须有独立权限与授权设计，不能由“专业角色”隐式授予。
4. **创建时不请求模型。** agent profile 是由用户确认的本地数据，不需要消耗额度或上传资料来生成。创建后 Noema 建立一间独立 DM，并写入“你和 X 已成为联系人”的系统事件；后续同一 agent 可作为群成员复用相同身份，各 room transcript 仍隔离。
5. **归档代替硬删除。** specialist 可归档与恢复。归档保留身份、DM、群聊历史与任务来源；不出现在新群聊成员选择中，也不能作为新回复者或新任务承接者。已有群聊仍可查历史，但本轮只允许选未归档成员。Noema 核心身份不可归档。此版本不物理删除任何已有对话事件。
6. **身份数据单一归属。** Noema SQLite 的 `social_agents` 是身份/资料/归档状态唯一来源；`social_rooms` 和 room membership 只引用同一个 agent ID。prompt 为当前结构化资料的可再生表示，不新增 profile 文件、插件层或个人 agent 市场。
7. **能力边界要可见。** 新联系人创建后可私聊和加入群聊，但当前版本只保证对话；界面不得把专业范围写成已验证技能、工具能力、运行时或任务执行承诺。

## 替代方案

- **继续只保留源码内置联系人：**成本最低，但产品在“用户拥有自己的 agent”这一核心假设上不可实际使用，只有开发者预设身份。
- **让 Noema 自动从聊天创建好友：**更接近愿景，但可能把一次性想法误判为长期关系并制造用户不想要的联系人；在没有成熟 agent 资料治理前不自动创建。
- **开放完整系统提示词编辑：**自由度高但把 harness 维护负担交给用户，与用户希望按人的专业实践创建联系人、不想维护 prompt 的方向不符。
- **创建时同步调用模型扩写 profile：**会增加费用、网络依赖和隐私传输，并容易把角色扮演语气误当真实能力；首版不做。
- **删除联系人及其历史：**容易造成关系/来源链破坏；使用可逆归档保护历史，并让新交互停止。

## 后果与重审条件

- 用户可以第一次在 Noema 中建立自己命名、描述、可私聊并可拉入群聊的 specialist identity；这使“我的 agent”从固定 seed 变成可操作能力。
- `social_agents` 需要 additive schema migration 与归档过滤；归档不应破坏既有 room membership、消息来源或 task provenance。
- 只证明“可创建并持续寻址的身份”不等于 agent 有独特人格、专业水平或会自主成长。若用户实际只创建不再互动，或 profile 描述不能带来可感知差异，应重估好友 roster 是否值得作为主结构，而非增加更多 agent 数量。
- 若后续要修改 profile，须决定运行中任务如何保留 profile snapshot；本 ADR 不授权回写任何已发生任务或历史消息。
