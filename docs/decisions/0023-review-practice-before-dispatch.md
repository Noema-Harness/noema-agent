# ADR 0023：派发前审阅跨房间实践候选

- 状态：接受为 M1 安全与透明度边界
- 日期：2026-10-19
- 决策者：助手，在用户委托的 Noema 产品与工程范围内决定
- 依据：用户确认了熟悉的社交聊天与持续好友方向，并委托产品决策；Issue #97 的真实 DSH 运行证明候选可跨房间进入任务，但候选含触发/边界不等于执行模型会正确判断它是否适用。
- 关联：Issue #2、#97、#99；ADR 0015、0022

## 问题

聊天中的通用“参考同项目已核验经验”开关只表达用户想参考某类过去经验，不代表用户看过或批准了当前特定的模型生成候选。若 Noema 将候选自动放入 DSH 上下文，执行模型还必须自行判断 trigger/limits 是否匹配；提示文本不是可靠的权限边界。候选在来源任务卡可查看，但用户在另一个房间启动新任务时通常看不到它。

## 决定

只有当 `reuseCase=true` 且当前同 agent / canonical workspace / 跨 room 存在一条 `available` 候选时，Noema 才在用户选定工作区、任何任务记录或模型请求产生之前，展示一次 Windows 原生确认。确认中显示：当前任务、候选触发条件、做法、适用边界、形成房间与基础案例来源。

用户只能选择：

1. **试用候选一次**：持久化候选完整快照，并在本次任务中作为低权威上下文发送。
2. **不试用候选**：保持候选 `available`，本任务不接收它；退回原来已由复选框授权的普通已核验案例路径。
3. **取消任务**：不写 task、不 claim 候选、不调用 DSH。

决策由 Noema 主进程控制；执行 agent 不能自行 claim、改变或永久晋升候选。候选没有时不弹额外确认。现有目录/第三方模型披露仍有效，确认中再次指出候选和当前任务会随工作请求送往已选的免费模型路由。

## 状态所有权与失败行为

- `SocialChatStore` 仍拥有候选和 task 快照；用户的逐任务决定只在派发前决定是否将候选快照复制到 task。
- 用户选择“不试用”时，普通 `caseSnapshot` 可继续作为此次显式经验复用的结果；候选仍可供未来另一次审阅。
- 用户取消、窗口关闭或确认回调失败时，不创建 task，也不 claim 候选。
- 一旦 task 已启动，后续撤回不倒写它的快照；原有一轮后 trial 状态及撤回规则不变。
- 不新增持久的 preference、评分、relevance 模型或隐藏学习状态；不增加模型调用。

## 替代项

- **只依赖 prompt 告诉 DSH 检查 trigger/limits：**真实 DSH worker 有机会在候选不适用时仍受其影响，执行模型不是权限/选择控制面的可靠所有者；拒绝将它作为唯一保护。
- **新增 AI relevance judge：**会额外消费不稳定的免费请求，且引入第二个模型判断决定第一个模型能看什么；没有证据证明它更可靠，暂不采用。
- **永久不再跨房间带入候选：**最安全但丢失了本轮验证的核心假设；保留候选的一次性 opt-in 试用。

## 验收与重审条件

- Service tests 覆盖 trial / case-only / cancel 三个分支，确认只有 trial 创建 `practiceSnapshot` 并 claim 来源候选；case-only 不动候选状态；cancel 无 task/worker。
- Windows synthetic E2E 验证实际的 dialog decision callback 与 task context；live DSH 仍是可选实验，不进入 CI。
- 若用户觉得每次候选弹窗繁琐、候选很少值得试，或等价的内联预览可以降低打断而保留明确选择，则重审窗口形式；若候选内容仍然大多没有可迁移价值，撤回本候选机制，而不是添加更多门控。
