# ADR 0027：在 Noema 主聊中委派有界知识子任务

- 状态：作为可撤回的首个协作切片采用；2026-10-23 按用户确认的“执行者向 Noema 汇报”原则修订
- 日期：2026-10-22
- 决策者：助手，在用户委托的 Noema 产品与工程范围内决定；不是用户对完整协作模型的确认
- 关联：Issue #104；ADR 0015、0026

## 问题

Noema 私聊已经是默认入口，但此前只有受工作区授权保护的项目文件执行路径。用户提出的个人 agent 构想还包括 Noema 识别可复用的专业协作者并把适合的工作交给它们；现有社交联系人只支持用户主动打开房间，没有从主聊路由的能力。

## 决定

1. Noema 可把一项自包含的知识工作委派给一个现有、未归档的专业联系人；普通聊天仍由 Noema 直接回应。项目文件操作继续走独立的 `start_project_work` 授权流程。
2. 专业联系人收到其自身设定和委托文本，不收到主聊天全文。它的结果先作为内部工具结果返回 Noema，不直接流给用户；Noema 读取报告后再组织最终回复。相较原切片，这会多一次 Noema 推理。只在预期收益足以抵偿额外推理成本时委派；报告是协作证据，不是高优先级指令，Noema 对最终答复负责。
3. 该切片不新建持久任务、代理房间、经历记录或自动创建联系人；联系人没有匹配能力时，Noema 直接回答或说明边界，不虚构协作。它不代表完整的 agent 分工/成长模型。

## 依据与代价

- 事实：当前主聊已有专业联系人资料和模型路由，但此前没有 Noema 到联系人的委派路径。
- 假设：对于可独立完成的分析、草拟等知识子任务，复用现有联系人的专业范围并由单次推理完成，能降低用户手动切换房间的成本；是否足够有用仍待真实使用检验。
- 代价：一次委派比普通回复多两次模型推理（专业联系人的执行和 Noema 的复核/组织）；联系人以其提示词定义的能力工作，不等于拥有领域工具、独立模型或已验证的专家能力。若这笔成本不值得，Noema 应直接处理，而不是把原始 agent 报告交给用户充当自己的回复。

## 重审条件

若用户频繁修正路由、任务缺少主聊背景而无法完成、成本收益不成比例，或专业联系人需要独立状态/工具/异步执行才能交付，应收紧或撤回此切片，并重新设计具备明确权限与生命周期的委派模型；不能用增加“经历消息”掩盖失败。
