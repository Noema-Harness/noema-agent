# ADR 0009：在根对话中保留网关报告的实际模型路由

- 状态：接受为 M1 可逆观察能力；不代表模型身份连续性已解决
- 日期：2026-10-14
- 决策者：助手，在用户委托的 Noema 生命周期自主决策范围内

## 问题

Noema 当前持久化用户选择的路由别名（例如 `auto:noema-free`），却不保存 FreeLLMAPI 实际报告的提供方/模型。别名可能在不同轮次落到不同上游，因此用户看见同一个 Noema 回复，却无法知道本轮具体由什么路由生成；同时，任何关于“固定模型”“同一条件下比较”的本地记录都缺少网关侧证据。这削弱了用户判断连续性变化来源的能力。

FreeLLMAPI 官方 API 文档说明响应包含 `X-Routed-Via: <platform>/<model>`，并将它定义为实际服务本次请求的路由。该值是网关报告，不是模型自我报告，也不证明回复质量或模型行为由某个记忆导致。[API 响应头文档](https://github.com/tashfeenahmed/freellmapi/blob/main/docs/en/api/01-rest-api.md)

## 决定

1. 在每条 Noema assistant 消息的尝试记录上保存 `X-Routed-Via` 元数据；一次对话重试属于新的 assistant attempt，不混入旧尝试。使用有界列表以支持未来同一回答内多个模型请求；当前主对话只发起一条生成请求。
2. 来源仅为本机 FreeLLMAPI 响应头。保留网关报告的 `platform/model` 值并解码百分号编码；不从所选别名、模型正文或错误文本推断上游模型。
3. 路由缺失时标为“未报告/未知”，不回退显示成用户选择的别名，不阻止回复完成。旧记录状态保持“未采集”，避免误说旧网关没有提供该头。
4. 用户可以在 assistant 回复的次级详情中查看所选路由及网关报告的实际路由。它是对话来源信息，不成为常驻仪表盘，也不声称 Noema 已跨模型保持相同行为。
5. 元数据只在本地 SQLite 随对应回复保存；不新增模型调用、上游数据发送、权限、日志中的用户内容或对 FreeLLMAPI 的管理能力。它与对应 root message 一同保留/删除。
6. DSH worker 的内部模型调用不在本 ADR 范围内；除非 DSH/FreeLLMAPI 提供可验证且可绑定到任务的路由事件，Noema 不猜测 worker 使用的模型。

## 备选方案

- **只显示用户选择的 `auto:noema-free`**：这是输入路由而不是实际响应来源，已无法满足“本轮由谁服务”的问题。
- **显示所有 FreeLLMAPI 路由作为运营面板**：将用户带入供应商运维，且不能说明 Noema 对这一轮实际发生了什么；拒绝。
- **不展示路由以维持界面简洁**：保留在本地仍可支持排障，但用户无法辨别上游变化；因此以折叠详情作为默认呈现。

## 后果与验证

- 用户可在不离开对话的情况下看到网关报告的实际来源；同一根对话中模型切换和用户可见输出被放在同一时间线上。
- 隔离的真实 E2E 结果同时记录请求别名和网关报告的实际路由，以便未来成对比较时排除实际模型不匹配的样本。
- 该信息依赖 FreeLLMAPI 版本与响应头。Header 缺失、截断或网关错误时保持未知，不将“未采集”说成“某模型未参与”。
- 一条实际路由记录只说明请求被路由到哪里，不证明模型完整处理了上下文、遵循了互动调整、或解释了输出差异。
- 真实 FreeLLMAPI 生成验证仍受本机 7890 代理连接稳定性影响；单元测试只验证解析和持久化，不能替代运行验证。

## 重审条件

- FreeLLMAPI 改变或撤销路由头语义。
- 实际路由信息在根对话详情中增加了噪声，或用户不能据此理解“所选路由”和“上游来源”的区别。
- 后台 DSH 任务可提供更可靠的路由证据；届时以任务维度独立设计，不能将根回复元数据冒充 worker 来源。
