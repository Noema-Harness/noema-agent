## 当前交付重点

R0 的真实使用闭环尚未完成价值验收。实现与局部验证继续按路线推进；用户不再需要逐模块中途验收，既有待审内容统一留到 Noema 完整落地后测试。长时间真实客户端/模型测试由用户执行，助手只准备诊断入口、做短时定向检查并分析用户提供的结果，不反复启动长测。

R4 的个人记忆闭环（OpenSpec `personal-fact-continuity`）已具备本机实现与定向验证：由用户明确保存或手动维护，Noema 主聊相关时按需检索，专业成员会话隔离，用户可查看、纠正、删除和暂停；整体桌面使用评测留在 T-10。当前代码切片是用户控制的一次性回访提醒（OpenSpec `user-controlled-followups`）：主聊明确授权或用户手动安排后，持久保存并在到期时发出本机通知；不在到期时调用模型或自动执行任务。完成后统一桌面评测留在 T-11。

真实 AI 价格追踪项目仍有尚未证实的链路：最近一次真实尝试没有建立新的派单记录或工作任务，工具续答此前也出现过 `provider_unavailable` / `ERR_CONNECTION_CLOSED`。现有证据不能将断流归因于单一网络原因。修复 `cd56365` 的两项针对性服务测试通过，但它们不能证明真实路由闭环。当前不修改用户生成的 `NoemaPriceTracker` 工作区，也不为重复撞测发起付费请求。成本优化的代码改动和离线验证已完成；自然 usage 与账单收益仍未确认，转入下方统一测试表，不再作为助手继续扩展调研的理由。

助手只做足以指导开发的短时本地验证，不替用户完成长测。用户测试后可按交互 ID 导出一条记录：`npm --workspace noema-desktop run diagnostics:model-usage -- --interaction=<交互ID>`；诊断文件保存在 `.work/runs/`。不把“待统一测试”视为通过，也不因某条测试尚未执行而反复提醒或停住无关模块的开发。

成本工作分为识别成本与减少成本，避免把“加了埋点”误当成“已经省钱”。截至 2026-11-01 本机 11:38 的只读账本共有 14 次成功 DeepSeek 社交/项目请求、1 次失败且无 usage：成功请求输入 279,820 token，缓存命中 140,288（50.1%）、未命中 139,532，输出 5,822。分场景命中率：项目工具续答 7 次为 65.9%，主聊项目模式 2 次为 23.9%，项目群 1 次为 3.6%，旧标签社交回合 4 次为 23.8%；尚无 root_chat、成长或足量闲聊样本。三个可归组的交互分别包含 4、3、1 次请求，两个多请求交互输入量为 101,792 和 53,258 token。按周末非高峰公示价估算，这 14 次模型 API 约 $0.02484；失败请求是否计费、Tavily 与其他供应商费用不在此数内，也不能据此估算用户当前余额。该样本早于 12:18/12:38 的最新缓存前缀改动，因此只作基线，不代表优化收益。

最近一次可见的请求记录中，8 个工具定义共 17,551 字符，对应 14,491 输入 token；一次项目续答请求字符 44,083–45,918、消息数 21–23、工具数 4，输入 25,812–26,614 token。工具定义中 `manage_project_plan` 单项约 9,667 字符。现已按协调者/成员权限生成不同 schema：协调者工具减少 39.8%，成员工具减少 72.0%；其余工具不变时，对样例整组 schema 的字符估算分别减少 21.9% 与 39.7%。这些都是可复现的载荷字符变化，不能替代 tokenizer 或账单证据。代码已把变化的项目/成员/工作项值从 schema 移入请求上下文，服务端权限校验保留；稳定 schema 的实际缓存与费用收益尚待更新客户端自然请求验证。成本专项新增可空 `interaction_id`，将同一主聊 turn、社交回复/专家交办、项目执行任务与后台任务中的 API 和 DSH 请求归组，并从权威对话/任务表读取当前状态；文件核验及后台回复单独呈现，旧行保留未知，不采集正文。Tavily 每次搜索的 credits 与 request ID 现单独按交互记录；请求失败且没有 usage 时仍记为未知，网页直连读取没有另计服务费。Tavily credit 的货币成本取决于用户账户计划，当前只记 credits，不冒充统一账单金额。

源码结构维护已在提交 `395858f` 完成并推送，依赖边界由 `npm run source:check` 持续检查；这只改善后续维护起点，不代表 R0 价值验收。成本专项已建立按交互归组的模型 usage 和外部搜索 credits 账本，并完成多项低风险优化：协调者计划 schema 字符数减少 39.8%，成员版减少 72.0%，普通主聊闲聊时省略无关的既有项目计划/群聊工具、项目清单及对应行动提示；服务端授权校验保持不变。闲聊 fixture 的项目 schema 从 11,712 降到 3,254 字符（−72.2%），行动提示另减少 195 字符；字符变化不代表同等 token/费用降幅。Tavily per-call credits 也已单独记录。最新只读 usage 基线见上段：14 次成功请求加权缓存命中率 50.1%，不同路径差异明显，且全部早于最近两项缓存前缀调整。普通主聊项目模式的 13,703 schema 字符和项目成员续答的 8,116 字符仍值得按自然调用观察；它们是请求结构数据，不等同于 token 成本。最近的重试审计还发现 RootAgent 曾在 `provider_error` 后自动重发模型请求，包括已有部分输出的轮次；现在仅对“上游明确不可用且尚无输出”保留一次自动恢复，其余由用户显式重试。社交请求已将按轮变化的项目/成员资产快照、经历简报和条件指令移到对话历史之后、当前输入之前；定向社交服务测试 26 项通过。2026-11-01 又固定了 RootAgent 的网页读取工具 schema：用户 URL 不再写进 schema 的动态 `enum`，服务端仍按本轮原文逐条校验；55 项 RootAgent 定向用例通过，其中还确认模型提出用户未给出的 URL 会在网络请求前被拒绝。DeepSeek 项目工具续答现只在对象状态变化时追加最新快照，保持已发送请求前缀不变；27 项协作服务测试通过。未发模型请求。实际缓存收益待 T-08 中的用户自然使用记录确认；成本改动代码已完成，助手不再启动额外的付费长测。
