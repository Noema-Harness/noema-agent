# Noema 阶段总览

这里维护阶段目标与退出条件；只在阶段取舍或交付重点改变时更新。细任务与证据留在 OpenSpec change，避免再维护一套任务看板。

## 产品交付顺序

| 阶段 | 用户结果 | 转入下一阶段的依据 |
| --- | --- | --- |
| R0 个人 agent 闭环 | 自然交流可过渡到必要澄清、研究、判断与真实委托 | 在真实客户端理解进度、成果、失败与反馈；团队贡献和使用价值得到评审 |
| R1 可信聊天入口 | 能找到成员、项目、消息和来源 | 搜索范围、定位、键盘及空错状态实际可用 |
| R2 可控行动 | 工具行动可授权、停止、核验与恢复 | 多步执行、来源、数字、断流和重启不制造错误完成状态 |
| R3 持续委托与成长 | 成员资产、经历、归档与续接可靠 | 写入、报告、恢复和成长在持续使用中形成闭环 |
| R4 日常连续性 | 工作之外也能持续帮助用户 | 一个日常情境可用，并能纠错、删除、暂停与控制通知 |
| R5 可恢复发行 | 陌生机器可安装、升级与回退 | 干净安装、旧数据迁移、备份恢复和发行诊断有证据 |

## 当前交付重点

R0 的真实使用闭环尚未完成价值验收；共享计划、协作、搜索与工具等已有实现和服务验证，但不能据此宣告全阶段通过。项目成员现在可从同项目群最近 128 条含链接的已完成用户发言中读取明确给出的链接；读取范围不含 agent 消息，单回合仍最多三项。真实项目的一轮低成本验证已从历史用户消息成功读到 OpenAI 官方定价页，但读取后的模型续答遇到 `provider_unavailable` / `ERR_CONNECTION_CLOSED`，没有形成价格结论、团队提交或计划进展。下一步接续 AI 价格追踪真实项目：先查明这次续答断流发生在哪一层，再让 Noema 和团队沿现有计划继续，核对来源、提交、验收与主聊反馈；不把成功读取网页等同于项目闭环通过，也不以合成项目替代。

源码结构维护已在提交 `395858f` 完成并推送，依赖边界由 `npm run source:check` 持续检查；这只改善了后续维护起点，不代表 R0 价值验收。当前回到 R0：基于已有真实项目验证 Noema 如何接收成员报告、推进工作、识别阻塞并请求必要评审。下一项跨模块实现前先从具体失败或缺失的用户结果建立 OpenSpec change；不要再为源码整理单独开一条并行主线。
