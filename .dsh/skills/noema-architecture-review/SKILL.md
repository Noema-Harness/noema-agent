# Noema 架构判断

先明确当前用户要求和预期改善，区分参考方向与已经接受的实施决定。沿源码导航核对现有所有者和调用链，不将既有代码组织升级为不可改变的产品边界。

新增职责先检查平台、已有代码或成熟实现能否承担。明确状态来源、生命周期、权限、失败恢复和移除方式，比较复用与迁移的真实成本。

关键取舍记录在实际变更的设计中；未经采用的研究不成为当前指令。没有明确行为变更时，不制造产品规格或替用户选择一期范围。
