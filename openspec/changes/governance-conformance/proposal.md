# 治理一致性修正（change governance-conformance）

Plan: none

## Why

2026-11-19 的独立对照审查（E1–E36 逐条比对实现）发现 11 处偏差、1 处未落地、1 处编号断档：开工清单无机器门、写盘印记只提醒不阻断、净零审计没接进里程碑、批次模型与「历史只增」互锁、旧说法残留、索引状态未同步、E24–E26 编号写成 EE、E27 缺定义、验收页不刷新。

## What Changes

1. 批次模型落到「当前批次 + 批次历史」两行，`history.mjs` 三类批次行统一计为「批次」，不再互锁；归档 change 可作为待验收阶段的批次证据。
2. 进执行中加开工清单门：必须有 kickoff 文档且结构合格，条目执行层留 `- 开工清单：<path>（日期）`。
3. 写盘印记从提醒升为阻断：`precommit` 发现暂存区与命令写下的哈希不一致即失败，恢复只走 `check`/`move --restore`。
4. 净零审计收进三动词：`check net`；`milestone` 与 CI 都跑，净增未写基线即红。
5. 修文档残留与索引：README 三层/命令/落地状态、report 模板、`stage` 验收提示、条目细则里「退回执行中」改回「回决策重开」；README 标注试点与抽离挂起。
6. 修条目编号：E24–E26 前缀、E27 指称并入 E28；验收项按 E1–E36 逐条重写并重出验收页。

## 影响

只改治理工具与治理文档，不改产品行为（`apps/desktop/src` 无改动）。
