# 治理接口收敛（governance-interface）

Plan: none

## Why

治理接口按文档小节切分，而不是按 agent 的意图切分：进一次执行要被拆成「改批次」加「换阶段」，记录一轮要四个参数。于是正常的推进需要记住一串命令与参数，接口本身成了仪式。用户 2026-11-19 指出：机制不该变成繁文缛节（E35、E36）。

另外两类反复出现的失败：条目被原生工具或一次性脚本改写（E33），以及同一种过渡文档越开越多（M16）。

## What

1. 三个动词：`record`（轮次/待裁/已定/验收项/字段）、`move`（阶段与批次一次校验）、`check`（阶段规则包与恢复卡、验收页、过渡文档）；一意图一调用，每动词参数 ≤5，长文本走文件（E35）。
2. 单一写入口：写盘后把内容哈希记到 `.work/decision-writes/`，提交前校验暂存区哈希；恢复走 `move --restore --from <commit>`（E33）。
3. 批次续接：执行层只留「当前批次」与「批次历史」，重开后再进执行默认续接同一 change（E34）。
4. 过渡文档唯一性与就地更新：同 kind 只允许一份，`--write` 默认更新那一份，`--new "<理由>"` 才新建（M16）。
5. 净零：命令数 ≤3、参数 ≤5、门只减不增；`governance audit` 输出门数，新增门须合并旧门并在提交信息写净额（E36）。

## 影响

只改治理工具、规则包与文档，不改产品行为。旧命令保留两个里程碑的别名，删除日期写进 `governance/README.md`。
