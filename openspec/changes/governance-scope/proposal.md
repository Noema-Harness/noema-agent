# 让边界在提交时自动播报

## Why

「什么时候走治理，什么时候可以自由执行」目前只写在 `governance/README.md` 的边界一节里，要靠 agent 自己记住先读它。实际执行中这会出现两种偏差：小事被套上大流程，或者产品行为改动绕过了变更与规格。

其中「改的是产品行为还是测试/文档」「这次有没有写入条目数据」这些判断机器完全做得了，差的只是没人把它们说出来。

## What Changes

- `scripts/maintenance.mjs` 新增 `changeScope(staged)`：按暂存路径分成产品行为、条目数据、治理工具、文档/测试四类，输出一句话「本次改动 → 行为路径 / 自由执行路径」与对应的要求。`checkPrecommit` 把它作为提示放在最前面。
- `governance/README.md` 的边界一节补「机器管到哪、人管到哪」表，明确机器要求与人的判断各占哪一段。
- `scripts/decisions-view.mjs` 把旧格式条目单列、不再冒充开放条目，并标注「只读视图、怎么重新生成」。
- 测试：`scripts/maintenance.test.mjs` 增加 `changeScope` 三条分支的用例。

## 影响

只改治理工具与文档，不改产品行为与数据；不需要规格增量（skip_specs）。

## 不在本批

- 把「用户预期是否变了」也做成机器判定（做不到，只会变成打卡）。
- 视图的独立页面或插件形态。
