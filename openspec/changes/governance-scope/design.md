# 设计：边界在提交时自动播报

## 事实影响

- 类别：仅执行
- 依据：只改治理工具的输出与文档措辞，不改产品行为、数据与对外承诺。

## 用户决策

- 用户 2026-11-19：「你自己审查过了吗？你应该进一步对你实现的整体机制进行审查，并确保一切达到你所认为能做到的最好状态。而且，你修改后的情况似乎还是没有解释起初我们所说的问题，什么时候该走治理，什么时候可以灵活执行」——授权自行判断并补齐。

## 目标

- 提交时一句话说清这次改动走哪条路径，让「自由执行」有一个可见的入口，而不是只靠记忆。

## 非目标

- 不做「预期是否改变」的机器判定；不新增门（净额不增）。

## 取舍

- 只做提示不做门：错误分类的代价是误拦，而分类的输入（路径）足够可靠，提示即可纠正。
- 挂在 `precommit` 而不是新命令：不增加新命令，零净增。

## 用户可观察的改变

- 运行 `node scripts/maintenance.mjs precommit`（或 git 钩子）时，第一行提示变成「本次改动（产品行为 N 个文件 …）→ 行为路径 / 自由执行路径：…」。

## 手测步骤

1. 暂存一个 `docs/` 文件：`node scripts/maintenance.mjs precommit` 应提示自由执行路径。
2. 暂存一个 `apps/desktop/src/` 文件：应提示行为路径与活动变更要求。
3. 暂存 `docs/DECISIONS.md`：应提示条目数据只经命令写入。

## 验收

- `node --test scripts/maintenance.test.mjs` 通过（含新增三条）。
- `node scripts/maintenance.mjs precommit` 输出包含路径分类。
- `npm run check` 全绿。
