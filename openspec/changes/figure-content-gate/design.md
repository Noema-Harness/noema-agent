## 事实影响

- 类别：仅执行
- 依据：不改产品行为、数据与结构；改的是维护者的出图门机制和两张文档图的内容，属于执行规则。

## 用户决策

- 无：用户在 2026-11-17 已明确批准“重画图 + 章节级判断机制”的方向（“可以”），不需要再选方案。

## 目标

- 图的行或章节变化必须触发一次判断，而不是只更新摘要。
- 图内容与当前结构对齐：bridge 传输、执行后端可换、平台状态、计划项校准。
- 治理图能直接看到“提示层 / 事实流 / 机器门”三层。

## 非目标

- 不追求全自动生图：内容仍是维护者手写的 IR，机制只负责发现“没改”和“手改”。
- 不改 `docs/ARCHITECTURE.md`、`AGENTS.md` 的正文；不新增图。
- 不引入第三方图库或新的 CI 服务。

## 取舍

- 选“章节级 pin + 内容未变拒绝 + 理由入档”，而不是“比对整篇文档”：整篇比对照旧，无法区分无关的小改与结构变化；章节级更贴近图真正依赖的内容，代价是维护者要维护章节名单。
- 理由与该次章节状态绑定，而不是一次写下永久有效：否则一次“无需改图”会变成以后所有漂移的挡箭牌。
- `candidate` 只做内容摘要校验，不自动改写：图的表达是判断产物，机械重排只会制造假更新。

## 用户可观察的改变

- 无：README / AGENTS 引用的图内容更新，产品运行行为不变。

## 手测步骤

1. `npm run figure:check` 通过。
2. 修改 `docs/ARCHITECTURE.md` 的 §5 一句话后运行 `npm run figure:check`，应报“图依赖章节在出图后变化（5. 一次执行的路径）”。
3. 此时运行 `npm run figure:build`，应拒绝并提示用 `--sections-changed` 记录理由；带上理由后重出图并通过检查。
4. 不改图只改 `source.json` 的 candidate 后运行 `npm run figure:check`，应报 candidate 与出图记录不一致。

## 验收

- `npm run check` 全绿，`scripts/figure.test.mjs` 覆盖章节漂移、理由覆盖与失效、candidate 手改三类行为。
- 两张图的 PNG/HTML 已重出，治理图可看到“提示层 / 事实流 / 机器门”。
- 失败修法已写进 `docs/OPERATIONS.md`。
