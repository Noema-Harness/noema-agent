# 设计：成员经历可查看、可删、可恢复

## 事实影响

- 类别：行为
- 依据：新增用户可见的成员经历面板，并新增五个 bridge 操作；成员资产数据表与写入时机不变，规格增量写进 `openspec/changes/member-asset-review/specs/specialist-agents/spec.md`。

## 用户决策

- 卡片 #137 的「还没做」第 3 项已写明“成员经历的查看 / 删除，入口未定”，本次只把入口定为成员列表的一行按钮，不改成长规则（写入仍是复盘沉淀 + 模型工具）。
- 需要用户后续验收的是入口位置与信息量是否够用；如果用户希望编辑经历正文，那是另一轮（会改变“经历由复盘产生”的来源语义）。

## 目标 / 非目标

- 目标：用户能在成员列表打开「经历」，看到沉淀的来源、时间与内容；能删除一条经历并从历史版本恢复；删除/恢复都进版本历史，可追溯。
- 非目标：不做经历正文编辑（保留模型写入语义）；不做跨成员搜索；不改复盘写入规则与提示词注入规则；不改 schema。
- 取舍：
  - 入口放在成员列表行而不是成员资料对话框——资料对话框是创建/编辑表单，经历是只读产物，混在一起会让“改资料”和“看成长”互相干扰。
  - 删除走墓碑 + `reason`，不做物理删除：复盘可能写错，但删掉的经历仍要能在历史里查到是谁在什么时候删的。
  - 恢复只接受未删除的历史版本，且要求 `expectedRevision` 匹配当前版本，避免覆盖并发写入。

## 用户可观察的改变

- 成员列表每行有三个动作：`私聊`、`经历`、`归档`。点「经历」打开对话框，列出该成员的经历文件；没有经历时显示“还没有项目经历。完成项目复盘后会出现在这里。”
- 每条经历显示路径、修订号、来源项目名（没有来源时显示“手动维护”）、时间；展开可读全文。
- 展开后可见历史版本列表；当前版本可 `删除`（二次确认），历史版本可 `恢复`。删除/恢复后列表与历史刷新，并提示“已删除，可从历史恢复。”/“已恢复到修订 N。”
- 归档成员仍可查看经历，但按钮显示不可用并说明“已归档成员不能修改经历。”

## 手测步骤

1. 用 `npm run dev --workspace noema-desktop` 启动开发版，进入「成员」。
2. 新建或选一个专业成员；如果它还没有经历，点「经历」应看到空态文案。
3. 让该成员经历一次项目复盘（或用测试夹具写入一条经历），重新打开「经历」：应看到路径、修订号、来源项目与时间。
4. 展开经历，点「删除」并确认：列表里该经历消失，提示已删除；展开「已删除」历史能看到墓碑版本。
5. 在历史里对删除前的版本点「恢复」：经历回到列表，修订号 +1，提示恢复到哪个修订。
6. 归档该成员后再点「经历」：内容仍可读，删除/恢复按钮不可用并给出原因。
