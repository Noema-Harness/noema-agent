# 设计：记忆底座（个体级第一版）

## 事实影响

- 类别：行为
- 依据：新增用户可见的记忆面板与写入准入规则，新增 `agent_memories` / `agent_memory_audit` / `agent_memory_fts` 三张表（schema 43→44）；主聊与成员会话的读取路径从“手写个人记忆”改成“按状态过滤的条目检索”。

## 用户决策

- 用户 2026-11-17（三问回答）：第一版只做个体级；事实/承诺/约束需确认、情境/偏好自动生效可见可撤销；经验毕业=任务级评测+用户确认。
- 用户同轮纠正：记忆不是只在项目归档时交互，每一轮对话都可能读写——所以写入与检索都是每轮可用的接口，不是批次作业。

## 目标

- 每条记忆有来源、写入时间、有效时间、状态；能不能被检索由状态决定，不靠提示词自律。
- 事实类候选在用户确认前不进上下文；确认与撤销都写审计。
- 中文自然句检索 Recall@5 ≥ 70%（当前 25%，3-gram 展开实测 76.7%）。
- 失效可复现：被 `superseded` 的旧事实不再被检索命中。

## 非目标

- 向量检索、图结构、后台合并 agent。
- 项目级/团队级 scope 的检索（列已留，第一版只有个体级）。
- 跨设备同步、人格演化、旧 `social_user_memories` 的数据迁移。

## 取舍

- **单表 + 审计表**，而不是纯事件溯源：当前量级（≤10⁴）用视图取“当前有效”就够，事件溯源的成本（写放大、启动重放）换不来价值。
- **按 kind 决定默认状态**，而不是全局“先审后写”：如果所有记忆都要确认，日常观察会攒成待办队列，用户会关掉它；只把身份、承诺、约束这类写错代价大的挡在确认后。
- **FTS5 + 3-gram 展开**，而不是 embedding：本机实测 10⁵ 条最坏 81ms，且中文 trigram 已覆盖 ≥2 字子串；引入向量要新依赖与打包成本，收益在近义召回（实测仅 2/15 短板），留给后续按证据决定。
- **不物理删除**：撤销与替代都保留行，界面上隐藏；这样“它为什么记错了”才查得下去。

## 用户可观察的改变

- 设置里出现「记忆」面板：按 待确认 / 生效 / 已失效 分组，显示来源（主聊消息、项目、手动）、写入与确认时间；点来源可跳到原消息或项目。
- 新出现的候选记忆带「确认」「撤销」；被替代的旧记忆标「已失效」并可看到被哪条替代。

## 手测步骤

1. 打开设置 → 记忆，确认空态文案。
2. 在主聊让 Noema 记一条事实（如“我每周五晚上做项目复盘”），回到记忆面板：应出现一条「待确认」，来源指向那条消息。
3. 不点确认，再问一个会用到它的问题：答复不应表现出记得。
4. 点确认，再问同一问题：答复应使用该记忆，且记忆面板显示确认时间。
5. 让 Noema 更新同一事实（改成“每周六”），旧条目标「已失效」、新条生效；再问应只出现“每周六”。
6. 撤销一条生效记忆：它从上下文消失但仍在面板里可查。
