## 目标

- agent 有唯一状态（讨论 / 执行 / 验收），状态驱动规则取用，不再从条目阶段推导。
- 讨论会话成为一等对象：可开始、记轮次、滚动待裁、定案或切走归档、随时恢复并续编号。
- 条目退为账本：只记已定内容；条目阶段保留为记录字段。
- 命令净额不增：`stage` 改名 `state`，其余命令数不变；不新增门。

## 非目标

- 不实现执行态与验收态的细节规则（骨架见设计稿 §12.4，延展项 §12.9 第 1、2 项）。
- 不做可视工作台 HTML、多主体状态、记忆衔接（§12.9 第 7、8、11 项）。
- 不在本批迁移全部历史条目（§12.9 第 9 项单列）；本批只保证新命令处理现有数据。

## 取舍

- 状态与日志存 JSON（`governance/data/state.json`）而不是 markdown：状态是机器运行数据，不需要人读格式；由 `npm run state` 渲染摘要。
- 会话归档是「切走即归档」而不是显式命令：减少一次操作，历史仍可查可恢复。
- 讨论期禁止落地产品代码与机制改动：沿用现有行为门与提交门，只把提示挂到状态上，不新增门。
- 待裁项迁到会话：账本只收已定内容，避免同一条款在两处维护。

## 用户可观察的改变

- `npm run state` 打印当前状态、本次会话的结论与待裁项、下一步动作；`npm run state -- set <状态> --reason "…"` 切换并留日志。
- `npm run state -- round|wait|archive|resume|log` 管理会话；切换状态后旧会话自动归档，可恢复。
- `AGENTS.md` 的状态图替代阶段地图；规则包由状态取用。

## 手测步骤

1. `npm run state` → 显示「状态：讨论」「本次会话：…」「待裁：…」。
2. `npm run state -- set 执行 --scope changes/<name>` → 日志多一行「状态：讨论 → 执行（日期，原因/范围，义务：关闭）」。
3. `npm run state -- set 讨论 --reason "回来继续"` → 同一会话恢复、轮次续编号。
4. `npm run state -- round --conclusion "…"` → 会话轮次 +1。
5. `npm run state -- wait add --item "T1 …"`，再 `-- wait drop --item T1` → 待裁项增删。
6. `npm run state -- log` → 显示最近若干次切换与时间。
