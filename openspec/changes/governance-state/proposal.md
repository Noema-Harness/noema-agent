Plan: none

## Why

规则目前从「条目阶段」推导：没有活动条目时，agent 不知道自己该守什么；一条讨论必须先有条目才能开始；条目同时承担记录、状态与命令输入三种职责。这套结构是前面几十次修补的来源。

用户 2026-11-19 定形了新的生命周期（设计稿 v5 §12）：状态属于 agent（讨论 / 执行 / 验收，删除空闲），讨论会话是一等对象、不挂在条目上，条目退为「已定的账本」。

## What Changes

- 新增 agent 状态：`governance/data/state.json`（当前状态 + 切换日志 + 讨论会话）；`npm run state` 读 / 设状态、记轮次、增删待裁项、归档与恢复会话。
- 讨论态 v0：会话对象（主题、轮次、待裁项、证据指针、产出）、两种结束（定案 / 切走自动归档）、恢复续编号、产出边界（讨论期不落地产品代码）。
- 规则包按状态取用：`npm run stage -- <阶段>` 改为 `npm run state -- <讨论|执行|验收>`；`discussion.md` 重写为讨论态规则。
- 条目职责收缩：`DECISIONS` 只记已定内容；条目阶段保留为记录字段，不再驱动规则；待裁项从条目迁入会话。
- 不新增门；净额见设计稿 §12.6。
