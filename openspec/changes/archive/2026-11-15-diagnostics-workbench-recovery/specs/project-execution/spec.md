## ADDED Requirements

### Requirement: 诊断工作台区分空记录与读取失败并提供恢复

本机诊断视图 MUST 将成功读取后的空列表与读取失败区分显示。首次读取未成功时，记录数量 MUST 显示为未知；列表与选中时间线的读取失败 MUST 提供可重试操作。刷新失败但已有成功读取数据时，系统 MUST 保留旧数据并标明当前结果可能过期。

#### Scenario: 首次诊断列表读取失败

- **WHEN** 用户打开诊断视图且最近记录查询失败
- **THEN** 系统显示可理解的读取错误、未知记录数量和原位重试，不显示“暂无执行记录”

#### Scenario: 重试后列表读取成功

- **WHEN** 用户在列表读取失败后选择重试且查询成功
- **THEN** 系统显示实际记录或真实空列表，并允许继续使用诊断视图

#### Scenario: 选中时间线读取失败

- **WHEN** 最近执行列表可用但选中记录的时间线查询失败
- **THEN** 系统显示时间线读取错误和独立重试入口，不把失败呈现为空时间线

#### Scenario: 刷新失败时保留已有记录

- **WHEN** 至少一次读取成功后刷新查询失败
- **THEN** 系统保留已显示记录，并注明刷新失败而当前列表来自上次成功读取

### Requirement: 时间线筛选只影响呈现

诊断时间线 MUST 支持按模块和事件阶段筛选，并显示筛选后的事件数与总事件数。无匹配项时 MUST 提供清除筛选操作。筛选 MUST 仅影响当前时间线的可见事件，不得改变选中执行身份、事件覆盖缺口、用量数据或导出报告的事件范围。

#### Scenario: 按模块与阶段筛选事件

- **WHEN** 用户选择模块或阶段筛选项
- **THEN** 时间线显示同时匹配所选条件的事件和匹配数量，其他时间线信息保持可见

#### Scenario: 筛选没有匹配项

- **WHEN** 当前筛选组合不匹配任何事件
- **THEN** 系统显示无匹配状态，并提供恢复全部事件的操作

#### Scenario: 筛选后生成导出预览

- **WHEN** 用户筛选了可见事件后为同一执行生成导出预览
- **THEN** 导出仍按所选执行的完整受支持数据生成，不因 UI 筛选漏掉事件或覆盖缺口
