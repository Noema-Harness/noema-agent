# Proposal

## Why

诊断事件写入时会过滤未知字段并脱敏，但本地数据库中的详情在查询时过去直接解析，因此受损或被改写的记录可能泄漏字段，损坏 JSON 还会让查询失败。安全读取虽已补上，但如果静默返回空对象，用户无法区分“没有详情”和“详情不可读取”，不符合诊断缺口必须明确呈现的要求。

## What Changes

- 限制单条持久化详情读取大小，并在读取时重新执行字段白名单和脱敏。
- 为完整、过滤、不可读取的详情提供明确状态；损坏/超限详情成为时间线与导出中的覆盖缺口。
- 保持查询、导出和详情过滤故障与 Agent 业务执行隔离。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `project-execution`：诊断事件详情的安全读取与不可用状态必须可见，导出须保留该覆盖缺口。

## Impact

影响主进程诊断事件存储与查询服务、共享诊断 DTO、诊断时间线/导出预览、OpenSpec 的 `project-execution` 行为及对应存储/查询测试；不改变既有数据库 schema，不读取真实用户数据库。
