# Design

## Context

见 proposal。`web-source.mjs` 已提供公开地址校验、DNS/IP 边界、重定向限制、大小/超时上限、正文提取和截断；主聊也已有“仅从本轮用户消息读取精确 URL”的入口。项目成员目前只有 Tavily 搜索工具，没有可在已知 URL 上直接调用的读取工具。

## Goals / Non-Goals

**Goals:**

- 只把项目用户明确提供的链接开放给当前项目成员读取。
- 复用现有安全页面读取与公开来源附加机制，不引入搜索服务依赖。
- 让读取失败、来源数量上限、取消和不可信正文都沿现有行为处理。

**Non-Goals:**

- 不允许项目成员任意联网或自行发现新 URL；搜索发现仍使用独立的 Tavily 能力。
- 不改变 Noema 主聊已有的 URL 读取行为，也不开放执行成员访问其他会话的历史链接。
- 不自动把来源结论写入计划或替成员验收。

## Decisions

1. **搜索与读取分成不同工具。** `research_public_sources` 继续做 Tavily 搜索；新增的项目来源读取工具只接受当前项目用户消息或项目原始委托中出现的链接。这样搜索凭据缺失不会挡住已知 URL，也不会让读取工具变成任意浏览器。
2. **沿用用户来源的精确白名单。** 只检查项目原始用户委托与当前项目群的用户消息，校验角色为真实用户、消息已完成，并从文本提取 URL。Noema 或其他成员转述出来的 URL 不会自行获得授权。只为项目群成员提供该工具。
3. **每轮共用三项来源预算。** 直接读取和搜索读取共享 `projectResearchSources` 与三项上限；每个链接单独读取，成功来源随公开成果附加，失败链接不会被重试或作为证据。来源写入格式复用既有逻辑。
4. **页面读取完全委托现有网页读取器。** 工具不实现新的 HTTP 客户端；保留 HTTPS/HTTP 白名单、DNS 公网判定、重定向、内容类型、超时、响应大小及 Readability 提取约束。页面文字以不可信数据返回，并限制模型上下文长度。
5. **处理链接旁的中英文标点。** URL 提取按常见中文标点和其百分号编码形式截断，避免把相邻厂商名或说明文字并入 URL；实际请求仍以提取出的完整 URL 为边界。

## Risks / Trade-offs

- [某个用户消息里同时出现多个项目链接] → 只在当前项目群或其原始委托上下文开放，不遍历其他主聊历史；模型按当前任务选择链接。
- [用户提供的页面含恶意提示或过长正文] → 沿用既有不可信内容指导与正文/响应大小限制。
- [URL 被标点解析截断] → 提取逻辑覆盖中英文及编码标点，并用真实消息形态回归；读取失败清楚返回，不静默改成搜索。

## Migration Plan

无需数据库迁移、凭据迁移或新增依赖。旧项目继续使用搜索工具；当前项目用户消息中的已知链接会直接出现在工具白名单中。
