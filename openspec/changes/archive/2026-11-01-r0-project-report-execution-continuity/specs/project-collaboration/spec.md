## ADDED Requirements

### Requirement: 活动计划授权成员报告后的执行续接

系统 SHALL 将活动项目中状态为 `in_progress` 的工作包视作该项目已有委托范围。Noema 收到该项目成员的内部阶段报告后，可在工作包验收范围内继续本地文件工作，无需用户重复授权；续接必须指定报告所属项目、工作包负责人及准确工作包。内部报告不得授权执行处于 `blocked`、`pending`、`submitted` 或待用户评审范围的工作包。

#### Scenario: 成员报告后续接进行中的工作包

- **WHEN** Noema 收到一个活动项目的内部成员报告，相关工作包处于 `in_progress`，且其负责人是该项目中具备项目文件能力的成员
- **THEN** Noema 可按该工作包验收范围调用本地执行器，并传入准确的项目、工作包和负责人；不要求用户再次重述委托
- **AND** 工作区选择与数据流披露仍由用户在启动器中确认，确认前任务不算已启动

#### Scenario: 报告指向受阻或待用户判断的工作包

- **WHEN** 成员报告涉及的工作包处于 `blocked`、`pending`、`submitted`，或项目等待用户评审
- **THEN** 系统拒绝以内部报告作为启动依据；Noema 应先处理计划中的真实阻塞或等待必要用户决定

#### Scenario: 内部报告尝试越权指定其他工作

- **WHEN** 内部报告调用文件执行器，但未指定报告所属项目的进行中工作包，或指定负责人与计划负责人不一致
- **THEN** 系统拒绝启动任务并返回明确的无效调用错误

#### Scenario: 明确续接时先补足缺失的执行能力

- **WHEN** 用户明确要求继续一个活动项目，当前工作包因负责人缺少项目文件能力而受阻，Noema 在原项目增补合适的执行成员
- **THEN** Noema 可在同一项目工具循环中读取最新计划，将工作包改派给该成员并恢复为 `in_progress`，随后绑定准确工作包启动本地执行
- **AND** 工具循环须使用更新后的成员名单和计划状态；其他原因造成的阻塞不得被自动清除
