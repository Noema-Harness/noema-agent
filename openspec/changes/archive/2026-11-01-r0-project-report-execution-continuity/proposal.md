# Proposal

## Why

项目成员的阶段报告会回到 Noema 主聊，但现有指导仍要求用户本轮明确重述本地执行请求。这样，已经由用户授权并写入共享计划的进行中工作包不能自然续接，报告链路会停在“收到报告、询问是否开始”。

## What Changes

- 将活动项目中处于 `in_progress` 的工作包视作已有委托范围，使 Noema 能在成员报告后按原计划继续相符的本地文件工作。
- 限定内部报告启动的项目、执行成员和工作包必须与报告所属项目及计划负责人一致；受阻、待开始、已提交和待用户评审的工作不得借此启动。
- 修复 Noema 在主聊为明确续接的项目增补执行成员后，工具循环看不到新成员及更新计划的问题；只有把真实解除的能力阻塞反映到负责人和进行中状态后，才启动对应工作包。
- 保留工作区选择与数据流披露；未由用户选定工作区前，不创建或声称已启动任务。

### Modified Capabilities

- `project-collaboration`: 明确活动计划工作包如何授权成员报告后的本地执行续接。

## Impact

- 影响 `SocialChatService` 的项目报告工具校验与 Noema 的项目执行指导。
- 更新项目协作流程图和定向回归测试；不增加模型调用、数据库状态或文件权限。
