# Design

## Context

See proposal.md. 项目群工具已把授权限制在原始委托和当前用户消息，但真实项目的来源链接可能出现在更早的群消息中。来源查询需要绑定当前 `groupRoomId`，且不能把成员消息或其他房间的 URL 提升为用户授权。

## Goals / Non-Goals

**Goals:**
- 支持从当前项目群近期已完成的用户发言中读取精确链接。
- 查询保持有界；不注入完整历史消息，不扩大网页抓取器的网络安全边界。

**Non-Goals:**
- 不从 agent/Noema 发言、其他会话或外部网页中提取授权链接。
- 不新增持久授权记录、搜索服务或跨项目来源复用。

## Decisions

- 在 `SocialChatStore` 增加只读查询，按群聊 ID、`role='user'`、`sender_agent_id IS NULL`、`status='complete'` 和含 HTTP(S) 文本筛选，按最近顺序最多返回 128 条。每条消息可提取多个链接；授权查询另外显式合并原始委托和当前用户消息，确保二者不受历史窗口淘汰影响。每回合读取预算仍独立限制为三项。
- 保持来源许可与上下文注入分离：只把抽取出的精确 URL 暴露给 `read_project_source`；历史消息正文不进入模型上下文。
- 运行时调用再次计算同一授权列表，并沿用现有 URL 校验、重定向主机限制、每回合三项读取预算、失败记录和来源附加逻辑。
- 提取链接时剥离紧邻链接的中文右括号等自然标点，避免将用户排版误当 URL 路径的一部分。
- 不需要保留全部 user message：近期窗口足以服务当前项目连续研究，同时使查询和模型可见工具参数有界；旧消息链接过期后，用户可重新发送链接。

## Risks / Trade-offs

- [用户在群里分享的 URL 可能在较早阶段发送] → 128 条有界近期窗口覆盖当前规模；原始委托始终单独保留。
- [历史消息中的 URL 可能只是引用而非要求读取] → 工具只提供显式 URL，模型仍须判断相关性；每回合三项限额限制误读成本。
- [成员文本中复述了用户链接] → 查询只筛选用户角色及空 sender；授权来源不能由 agent 发言建立。
