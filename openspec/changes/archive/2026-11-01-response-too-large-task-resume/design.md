# Design

## Context

响应字节上限在 provider 流读取层实施。工具调用只在完整响应解析完成后交给执行器，因此超限时本次响应中的工具不会执行。执行器在请求前持久化 `ready_for_model` 检查点；成功工具的逐步结果已经写入检查点和执行步骤表。

## Goals / Non-Goals

**Goals:**

- 仅在完整安全边界上恢复任务。
- 保留既有对话与工具结果，不重放已成功操作。
- 让恢复请求明确缩短输出，降低重复触发超限的机会。

**Non-Goals:**

- 自动重试超大响应。
- 自动压缩或改写用户任务、项目历史或执行结果。
- 为未知副作用提供自动恢复。

## Decisions

- `response_too_large` 与可恢复 provider 失败共用现有检查点路径；恢复资格仍由 `ready_for_model` 检查点、任务引擎及执行步骤状态共同决定。
- 用户显式恢复时，在检查点末尾追加一条系统恢复指令。用稳定标记避免连续恢复时重复追加；不保存或重试未完整接收的模型响应。
- 数据层 SQL 恢复白名单、任务 hydration 的 `canResume` 和执行服务安全边界必须同时包含该错误码，避免 UI 与存储层资格不一致。

## Risks / Trade-offs

- [模型可能再次返回过大响应] → 仍由用户显式发起下一次恢复；恢复提示要求局部、简短输出，重复失败不会无限请求。
- [旧检查点含未知副作用] → 仍通过既有逐步执行记录拒绝续接。

## Migration Plan

无需数据库迁移；只扩展已持久化的错误码白名单和恢复消息。
