# 工作流闭环：把九步、六角色与出口写进治理链

## Why

2026-11-16 的只读复盘（治理框架 + 工作流编排 + 提示词融合）发现五处系统性缺口，且有真实事例支撑：

- `AGENTS.md` §1 写的是 5 步（选卡 → 立项 → 纵切 → 证据 → 归档），实际运行是 9 步（开场 → 定性 → 立项 → plan:check → 实现 → 自验 → 收口 → 归档 → CI 回收），缺的三步恰好最容易漏。
- 「六种文档角色」（约束 / 议题 / 计划 / 契约 / 证据 / 观察）与「三类出口」（正向 / 逆向 / 异常）只存在于本机 `.work/` 分析，仓库里没有这个说法，下一位 agent 看不到。
- 逆向链（撤销提交、替代决定、卡片回退、规则退役、验收撤回）没有流程位置；2026-11-16 行数预算被否时，条目内容被直接抹掉，过程没有留痕。
- 治理登记表里有 4 条标注「预防」的规则从未触发过真实失败（observable-sections、governance-no-product、skip-specs-product、source-boundary），与「规则只在真实失败处保留」的原则不一致。
- 提示词层存在优先级缝：用户级 `~/.dsh/AGENTS.md` 说「可逆、低成本、授权内的事直接做」，仓库治理要求「机制改动先待定、批准后执行」。2026-11-16 把设计批评直接当工单执行，就发生在这条缝里。

## What Changes

- `AGENTS.md` §1 从 5 步改为 9 步，逐步写明「读什么、写哪份文档、漏做什么会没有检测」；开场固定三问（收件箱 / 待定 / STATUS）。
- 增加「六种文档角色」与「三类出口」两节：每个角色回答什么、写在哪、出错谁咬；出口写明被否、门失败、执行失败、验收未过、CI 红、决定被替代、规则退役分别落到哪里。
- 提示词优先级：写明「机制 / 治理变更不属于可逆小动作」，用户级与仓库级冲突时以仓库治理为准并记录理由。
- 治理侧：4 条预防型规则逐条补触发证据，或降级为提醒；补一条低成本校验（卡片正文含「现在能做什么 / 还没做 / 证据」三段），是否加先看真实切口结果。
- 流程图与复盘结论入库：`docs/assets/` 放工作流图，README / AGENTS 链接；**先跑一次真实产品切口对照，再决定是否入库**。

## Capabilities

无（治理与流程变更，不改变产品行为）。
