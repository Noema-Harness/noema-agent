## 事实影响

- 类别：仅执行
- 依据：不改产品行为、数据与结构；改的是治理技能的定位与同步机制，属于执行规则。

## 用户决策

- 已定：技能形态与六步结构由用户在 2026-11-17 确认（“都可以”，m102771 / m102774）——独立技能 `noema-governance`，`noema-development` 保持模板定位。

## 目标

- 发现执行偏离治理预期时，有一份可照做的盘查方法：分类偏差、还原应有路径、留证据、定位到机制层、登记候选而不是立刻改机制。
- 正常开发轮不受影响：常规轮只加载 `noema-development` 模板，无需加载盘查流程。
- 两份技能都能同步到 `~/.dsh/skills`，`docs:check` 校验副本一致。

## 非目标

- 不把盘查做成每轮清单或指标表：那会诱导照表打卡，正是这次偏离暴露的问题。
- 不改 `AGENTS.md` 的流程正文（行数已到上限）；不改产品代码。
- 不做自动盘查工具：证据采样靠命令与判断，不新建检查脚本。

## 取舍

- 独立技能而不是并进 `noema-development`：目录描述负责路由，两个单一职责的技能比“模板 + 长诊断章节”更难退化成清单。
- 六步保留“登记候选待定”作为最后一步：盘查的价值在定位，落地取舍仍归用户；直接改机制会让同一次偏差变成新的既成事实。
- 反例只用真实事件（图门、门所有权、portable 报告期、状态词）：规则只保留在真实失败出现过的地方。

## 用户可观察的改变

- 无：技能只在 agent 侧按需加载，产品运行行为不变。

## 手测步骤

1. `npm run skill:install` 输出两条 `skill-install: OK`，`~/.dsh/skills/noema-development` 与 `~/.dsh/skills/noema-governance` 均存在。
2. `npm run docs:check` 通过；改动任一份仓库技能后重跑，应报“已安装的技能 … 与仓库不一致”。
3. 读 `skills/noema-governance/SKILL.md`：确认六步、产物、反模式与边界齐全，正常轮次不需要它。
