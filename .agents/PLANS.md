# Noema 执行计划

只为跨多轮、跨模块或明显高风险的工作创建计划。小任务直接做，不为流程创建文档。

每份计划写在当前 GitHub Issue 的 checklist 或其链接文档中，并包含：

1. 用户结果与当前已知事实。
2. 要改变的边界与明确不改变的内容。
3. 最少必要步骤及可独立验证的里程碑。
4. 主要失败模式、数据/权限影响及回滚方式。
5. 每个里程碑的通过条件与实际运行的检查。
6. 一个便于续接的最新检查点：已完成及证据、未决判断、下一步具体动作。

Issue 与 Project 是目标、验收和进度的唯一状态来源；长计划文档只保存技术步骤与证据，不再复制状态。新证据或用户调整可改变计划、Issue 和阶段依赖；保留变更理由，不为维护旧计划而继续执行已失效的方向。
