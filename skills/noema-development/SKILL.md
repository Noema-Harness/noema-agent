# Noema 开发：填写模板

本技能只做一件事：**给需要你手写的文本提供骨架**。状态机、门与规则在 `governance/`；命令与报错修法在 `docs/OPERATIONS.md`；入口是 `AGENTS.md`。

## 0. 先跑命令，不要凭记忆

- `npm run state`：当前状态、会话、待裁、当前状态的规则包。
- 切状态：`npm run state -- set <讨论|执行|验收> --reason "…"`（离开讨论会自动归档会话）。
- 不要手改 `governance/data/state.json`；不要另建记录系统。

## 1. 讨论态：会话与范围

讨论不需要先有范围；轮次只写差分，结论写进待裁或直接成范围。

```markdown
- 轮次 N（日期）：<一句结论>
  - 新增待裁：T1 <要裁什么>；T2 <要裁什么>
  - 已解除：T0 <因为什么>
```

定案时写范围（一句话也行，但要能被验收单元拆开）：

```markdown
范围：<给谁、解决什么、可观察的结果；已知边界与不做的事>
```

## 2. 执行态：验收单元与任务

范围拆成 2–5 个验收单元；每个单元进入时写 1–N 条验收项（D/C/R/H），可追加不可静默删。

```markdown
阶段 P1 <名字>：<这个单元证明什么>
- 任务 P1-T1 <可执行动作>（完成时附证据：命令与输出/文件路径）
- 验收 P1-A1 [D] <用哪条命令/测试判定，怎么复现>
- 验收 P1-A2 [C] <对照进入时写定的判据，逐条比>
- 验收 P1-A3 [R] <审查要查的风险点>（发现必须逐条处置：已修/延期/接受+理由）
- 验收 P1-A4 [H] <需要用户确认的预期理解>（只由用户签收）
```

进入阶段先答三条（`state -- phase check --id P1 --what/--gap/--split`）：这个单元证明什么、可能漏什么、要不要调整划分。

## 3. 验收态：判定与交接

- 通过 = D 全绿 + C 全绿 + H 签收 + R 全部处置；R 只出发现，不判通过。
- 判定三选一：通过 / 不通过（回执行修偏差）/ 预期有问题（回讨论改范围）。
- 交接写清：改了什么、证据指针、未验证项、已知风险、下一步。
- 收口由用户签收：`npm run state -- sign "<用户原话>"`；agent 不代签。

## 反模式

- 把验收单元写成文档章节：单元只存在于状态数据与工作台。
- 自己写判据又自己改判据来通过：判据在进入单元时写定，只能追加并记录来源。
- 用「我试过了」代替证据：证据是命令、输出、文件路径。
- 没范围就先改产品行为：先回讨论写范围；纯实现级修复不必重开讨论。
