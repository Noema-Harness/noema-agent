# Noema 开发：填写模板

本技能只做一件事：**给需要你手写的文件提供骨架**。九步流程、条目结构、讨论规则、三类出口在 `AGENTS.md` §1–§2；所有命令与报错修法在 `docs/OPERATIONS.md`；本文件不重复它们。

## 0. 讨论、开工、执行

三个阶段，边界不许含糊：

- **讨论**：只写条目决策层、文档与调研，不动产品代码。每轮回复只以三种方式结束——「等你定 A/B」「我建议 X，等你点头」「已交结果，等你验收」。
- **开工请求**：进入执行前先进计划模式（`/plan`），用 `exit_plan_mode` 交开工清单——① 改哪些文件或模块；② 建哪个 `openspec/changes/`；③ 怎么验证。交完就停。
- **执行**：用户批准开工清单后才动代码。回答设计问题、选选项、含糊的「可以」都不算批准；拿不准就问「要我现在开工吗」。

条目里的决定绑原话：`- 决定：…（用户原话：「…」，YYYY-MM-DD）`，不写自己盖的「用户确认」。

## 1. 立项三件套

`openspec/changes/<name>/proposal.md`

```markdown
Plan: <卡片链接> # 治理变更写 Plan: none，并在 .openspec.yaml 写 skip_specs: true

## 为什么

<一句话说清要解决的失败或能力缺口，带可核对的事实>

## 改什么

- <改动点，含影响的文档与脚本>

## 影响

- 代码：`apps/desktop/...`（无则写“无产品代码”）
- 文档：<PRODUCT / ARCHITECTURE / DECISIONS / OPERATIONS / STATUS 中实际会动的>
```

`design.md`

```markdown
## 开工声明

- 计划先于代码：本变更的提交信息含变更名，tasks 记录证据

## 事实影响

- 类别：行为 / 结构 / 取舍 / 仅执行（四选一或多选）
- 依据：为什么属于这一类（机器门按它核对 docs 与 specs 配对）

## 用户决策

- [ ] <问题>：候选 A / B；建议 A；确认前不执行（没有就写“无”）

## 实现选择

- <维护者判断，可被推翻>

## 用户可观察的改变

- <用户能看到的差异>

## 手测步骤

1. <命令或点击路径>
```

`tasks.md`

```markdown
- [ ] 1.1 <动作>（验证：<命令或可观察结果>）
- [x] 1.2 <动作>（验证：<命令 + 输出摘要，如 887/887>）
- [ ] 2.1 [用户] <只有人能判断的验收>（完成后写「用户确认：YYYY-MM-DD」）
```

## 2. 决议条目

**先确认这一条该存在**：只有用户要求定一件事、需要用户在多个方案里拍板、或跨轮次/不可逆/代价差一个量级的取舍才写条目；普通实现、修复、只补验证都不写，证据放提交信息或 change。条目由用户发起或确认，agent 不自行开条目，也不把候选写成决定（机器门校验来源与「用户确认」日期）。

骨架：

```markdown
## <阶段标记> [#<issue>](https://github.com/Noema-Harness/noema-agent/issues/<issue>) D-YYYYMMDD-<slug> <标题（范围变了就改）>

- **阶段**：决策中 | 执行中 | 待验收 | 已收口
- **结构**：入口 / 字段 / 校验 / 命令（仅机制类，≤10 行）
- **来源**：用户 <YYYY-MM-DD> <用户在哪一轮提出、说了什么>（必填，以「用户」开头；机制类写清结构）
- **阻塞**：<哪条 task / 下一步> | 无

#### 1 决策

- 要定：…（用户确认后改写成 `- 决定：…（用户原话：「…」，YYYY-MM-DD）`）
- 纪要：随讨论追加，含被否决的选项与判断
- 重开：<新想法>（用户确认 YYYY-MM-DD）；原结论标注“已被重开”

#### 2 执行

- 决策中先写一行 `- 未开始：定案后进入执行`；进入执行后改写成 `- 批次：changes/<name>（commit <sha>）`，发现另起一行。执行层只有这两样：进度看 change 与看板，不抄进条目；没有批次指针，机器门不放行阶段推进。

#### 3 验收

- 决策中先写一行 `- 未开始：定案后进入验收`；交付后改写为可勾选清单
- [ ] <可观察结果> — 怎么验 — 怎么跑（在 GitHub 勾选；勾完 `npm run decisions:sync` 收口）
- 用户确认：YYYY-MM-DD（收口时写）
```

三层随阶段推进填写：**讨论期只写决策层**，执行与验收留 `- 未开始：…`；字段只有 `阶段`／`结构`／`来源`／`阻塞` 四个，不再写 `**状态**`（阶段已经表达状态）。机器门会拒绝决策中却写满执行/验收的条目。
