# 条目收口（会议总结 + 重构）

设计获批后执行。它把讨论期压成可长期保留的决定记录。

## 产出 A：会议总结（≤1 页）

```
# 会议总结：<主题>
- 条目：<D-…>；设计：<design 文件指针>
- 决定一览：E1…En（编号 + 一行动词短语 + 原话 + 日期）
- 影响面：文件 / 门 / 流程
- 不做与风险
- 例外落地回顾（若有）
- 遗留问题去向（卡片 / 下一条目 / 明确不做）
```

## 产出 B：条目重构

- 决策层：`- 决定：…（用户确认：YYYY-MM-DD，原话「…」）`、E 一览（编号 + 一行短语）、关键不变量（≤10 行）、`- 设计：<指针>`。
- 待裁清空；草案并入已定细则；已定细则只留对执行有约束力的内容。
- 讨论记录移出条目（留在 git 历史与设计文档附录）。
- 执行层：`- 批次：changes/<name>（commit <sha>）`；验收层：由设计生成的可勾选清单。
- 阶段 → `执行中`。

## 批准判据

- 条目变短，仍能回答「决定了什么、去哪看细节、下一批是什么」。
- `npm run docs:check` 通过；决定行原话与日期真实存在。

## 退回

收口后发现设计遗漏 → 阶段退回 `决策中` 并写原因；不在执行层补叙事。
