# 讨论态规则包

进入方式：`npm run state -- set 讨论 --reason "…"`（工具会把本文件与恢复卡打进输出；不需要先读文件）。

## 这个状态做什么

- 把要解决的问题说清楚：约束、取舍、可接受的代价、不做什么。
- 产物只有两类：**证据**（调研、复现、草稿、探针）与**结论**（一段可执行的范围，或明确不做的理由）。
- 证据放 `.work/`，结论进会话（`state -- round`），不新建平行文档。

## 怎么记

- 每轮只记差分：`npm run state -- round --conclusion "…" [--change "+支持 X / -放弃 Y"]`。
- 有需要用户拍板的事：`npm run state -- wait add --item "T1 …"`，用户答完用 `wait drop`。
- 待裁清单是滚动的：解除的就删掉，别让旧问题留在清单里。
- 中断时在会话里补一行 `- 中断：<情况>，返回后继续第 N 轮`，回来覆盖它、接着原轮次。

## 怎么结束

- **定案**：写清范围（`state -- scope "<一句话/设计稿/里程碑>"`），然后 `state -- set 执行`；
  有设计的，设计稿放 `.work/`，范围里指过去。
- **搁置**：`state -- archive --ending 搁置`，说清为什么搁置、什么条件下恢复。
- 切走即归档，回讨论态会自动恢复最近一次会话并续编号。

## 边界

- 这个状态只产出证据与范围，不改产品代码、不动验收产物。
- 讨论里发现要改的东西属于实现级（不改用户可观察行为）：直接记进范围，执行态去做。
- 检查项：`gate:status-today`（交付记录的日期事实）、`gate:source-boundary`（代码目录约定）。
