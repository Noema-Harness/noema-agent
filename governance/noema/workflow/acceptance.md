# 验收

任务做完、总体审查记过，才进得来。这个状态下 agent 只做两件事：核对自己的活，等用户签收。

## 做什么

- 自己再核一遍：范围里写的东西是否都在，任务的标准是否真的满足，证据是否对得上文件。
  发现新的问题，写成发现并处置，而不是悄悄补上。
- 请用户判断，只能由用户说：`npm run state -- sign "用户原话"`。
  agent 代填、占位、改写过的句子都会被拒绝。
- 签收后收口：`npm run state -- close`（归档进 `governance/data/history.json`，焦点清空）。
- 不通过就回执行：`npm run state -- set 执行 --reason "还差什么"`。

## 检查

- [ ] gate:status-today 签收前后能用到哪变了就更新 `docs/STATUS.md`。
- [ ] 没有未处置的发现；延期与接受都写清了理由。
- [ ] 每一条任务证据都能被第三方复核（命令、文件、截图）。

## 不要做

- 不替用户判断「可以交付」；那是用户的活。
- 不在验收态继续加功能（那会绕开审查）。
- 不把签收写成「符合预期」这类自己的话。
