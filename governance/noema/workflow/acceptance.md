# 验收段规则包

切片完成、准备交给用户验收时读这份。验收的目标是让用户能在 15 分钟内自己确认，而不是听汇报。

## 进入条件

- 执行段切片全部完成，或明确阻塞且剩余部分已写清。
- 执行交接数据已生成（`workflow/transition/handoff.md`）。
- 条目阶段仍是 `执行中`（验收通过后才转 `待验收 → 已收口`）。

## 验收页

由条目验收层 + 交接数据生成，渲染成可照做的页面：每条验收项写清「做什么 → 期望结果 → 证据在哪」。

## 三种标记

| 标记 | 含义 | 谁做 |
|---|---|---|
| `[用户]` | 用户 ≤15 分钟可独立跑完 | 用户 |
| `[机制]` | 我跑测试或命令并贴证据 | agent |
| `[未验证]` | 为什么没验、如何验 | agent 写清，不用「应该没问题」代替 |

## 禁止

- 「功能正常」「没有报错」「看起来对」这类没有操作说明的验收项。
- 把 agent 自测写成 `[用户]` 项。
- 未经用户确认就勾选 `[用户]` 项。

## 不过怎么办

回 `决策中`（重开）并写原因：

```
npm run decision -- advance --entry <D-…> --stage 决策中 --reason "<哪一处不过、说明决策漏了什么>"
```

工具会在验收层留一行「重开：<原因>（日期）」，并把执行层与验收层还原成占位。回到决策阶段补齐决定与执行范围后，重新批一次（清单可以很短），再进执行、再转待验收；不因一次不过就重写整个验收层。

## 收口

- 只有用户能确认收口；确认时写 `用户确认：YYYY-MM-DD` 与确认原话。
- 从验收页导出验收报告（模板 `workflow/transition/report.md`）：勾选表 + 证据指针 + 原话与日期 + 遗留项去向。
- 遗留项进卡片「还没做」、下一条目或明确不做，不留空。

## 检查项

- 用户验收必须带确认日期：`gate:user-acceptance-date`。
- 任务未完成不得归档：`gate:milestone-tasks`。
- 交付后卡片正文同步：`gate:milestone-card-body`。
- STATUS 是当天事实：`gate:status-today`。
- 引用的决议必须已确认：`gate:referenced-decision-confirmed`。

## 边界

- 用户验收是权限行为：我不替用户说「通过」。
- 机制类变更可由我跑测试并给证据，但用户仍可抽查；抽查不过按「不过」处理。
- 未验证项必须显式列出，宁可写「无」也不省略这一节。
